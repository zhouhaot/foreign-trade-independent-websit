# AGENTS.md — 外贸订单与单证管理系统（前端 Demo）

> 本文件面向所有参与本项目的 AI 编码代理（GPT / Codex 等）。Claude 代理请同时阅读 `CLAUDE.md`。
> **任何代理在开始工作前必须先读本文件和 `HANDOFF.md`；完成任何一个步骤或功能后必须更新 `HANDOFF.md`。**

## 1. 项目定位

- 项目：外贸订单与单证管理系统 —— **纯静态前端原型 Demo**，用于 UI / 交互 / 内容评审与迭代。
- 阶段：当前**只有前端原型，无后端**。最终后端规划为 Spring Boot，但现阶段**不要**引入后端代码、接口调用或构建工具。
- 目的：让需求方从视觉、组件、交互、内容四个方面提出修改意见，逐步收敛为整套前端。

## 2. 运行方式

- 直接双击 `index.html`（必须保持 `file://` 可打开）；或 `python3 -m http.server 8000` 后访问 `http://127.0.0.1:8000`。
- 登录页通过“演示角色”原生下拉框选择身份后点击“进入工作台”（假登录）；顶栏角色只读，切换账号必须先“退出登录”，再回登录页选择并重新提交。已登录时直接访问登录路由会返回工作台；退出后访问受限路由必须回登录页。下拉框保留原生键盘操作，账号/密码支持 Enter 登录；在下拉框内确认选项不得直接提交登录。
- 2026-10-04 起后续方案按真实落地标准规划。已确认范围为本公司内部员工、约 15 人、公司内网服务器或 NAS；具体并发数、部署硬件与后端方案仍待确认。本轮仅讨论架构，不撤销当前静态 Demo 的无后端/无构建约束，也不将假登录当作真实鉴权。

## 3. 硬性技术约束（不得违反）

1. **无构建工具**：不使用 npm / webpack / vite / 框架（Vue/React 等）。
2. **无外部依赖**：不引入任何 CDN、字体、外链图片、第三方 JS 库。图表用纯 CSS/SVG/Canvas。
3. **兼容 file://**：不使用 ES module `import`、不用 `fetch` 加载本地文件；JS 用普通 `<script>` 按依赖顺序在 `index.html` 引入；Mock 数据直接写在 `js/mock-data.js`。
4. **全局命名空间**：跨文件共享只通过 `window.U`（工具）、`window.Views`（视图）、`window.Actions`（交互动作）、`window.AppUI`（框架/路由）。新增共享内容挂到对应对象上，不新建全局变量。
5. **事件绑定**：统一使用全局 `data-action` 事件委托（见 `js/app.js`），视图函数返回 HTML 字符串；不要在内联 HTML 里写 `onclick="..."`，也不要在视图里手动 `addEventListener`（确有必要的局部例外需在 HANDOFF.md 说明）。
6. **界面语言**：简体中文；单证预览内的单据字段保留外贸英文惯例（Commercial Invoice / Packing List 等）。

## 4. 业务规则（Demo 必须体现，不得简化掉）

- 主流程：客户需求 → 询盘 → 报价 → 客户确认 → 生成订单。**订单只能由已确认报价生成，订单列表不得出现"直接新建订单"按钮**。
- 订单成立后两条**并行**支线（互不阻塞）：单证（制作→送审→审核通过→导出）与收款（登记→更新已收/未收）。
- 订单详情页三条状态**独立**展示：订单进度 / 单证进度 / 收款进度，不得合并为单一状态。
- 五类角色：系统管理员、外贸业务员、单证员、财务人员、业务主管。权限控制菜单 + 按钮 + 字段级只读：
  - 单证员：订单带入的核心交易数据只读，仅唛头/包装/备注类字段可编辑；
  - 业务主管：审核/异常处理，**不能自制自审**；
  - 管理员：无业务审批权。
- 已审核通过的单证再修改必须走受控修订，生成新版本 V(n+1)，不覆盖原版本。
- 金额规则：订单/报价总额 = Σ(数量×单价)；已收 = 收款记录之和；**不同币种金额不得合并**；改价审批通过时按目标金额等比调整明细单价以保持勾稽。

## 5. 目录结构与职责

```
trade-doc-demo/
├── index.html          # 唯一入口，按顺序引入 3 个 CSS + 9 个 JS
├── css/
│   ├── base.css        # 设计变量、按钮、.tag 状态组件、表单、表格、分页、弹窗、Toast、步骤条、开关
│   ├── layout.css      # A 浅紫侧栏、顶栏、面包屑、铃铛、登录页
│   └── pages.css       # 工作台卡片、订单详情三进度、单证三栏与纸张排版、统计图表、收款
└── js/
    ├── mock-data.js    # 全部样例数据（唯一数据源，文件头注明"仅用于原型演示"）
    ├── utils.js        # U：转义/金额/勾稽/tag/Toast/弹窗/校验/假分页/SVG 图/待办/会话
    ├── views-core.js   # 登录、工作台、客户/商品、404/无权限
    ├── views-sales.js  # 询盘、报价、订单列表、订单详情六页签
    ├── views-docs.js   # 单证列表、三栏预览审核页
    ├── views-fin.js    # 收款与应收、审核与异常处理
    ├── views-stats.js  # 统计分析（主管）
    ├── views-system.js # 用户/角色/字典（管理员）
    └── app.js          # hash 路由、菜单角色过滤、面包屑、身份展示/退出、铃铛、事件委托
```

新增页面的归属：按上表模块归入对应 views-*.js；新模块才新建文件，并同步更新本文件与 `index.html` 的引入顺序。

## 6. UI 规范

- 2026-09-30 选定 Ant Design Pro / Tabler / Metronic 融合参考；2026-10-04 需求方授权整套现代 UI 与动效落地。实际共享设计规范见 `DESIGN.md` 与 `.impeccable/design.json`；仍使用本地普通 HTML/CSS/JS，不安装模板依赖。
- 2026-10-07 按需求方确认落地 A：珍珠白工作区 `#f7f6fb`、浅紫导航 `#f0ecfb`、鸢尾紫主操作 `#6542d9`、薄荷青收款区 `#e4f6f0`、白色卡片；绿=成功、橙=待处理、红=异常/高风险。**所有状态必须同时有文字标签**（统一 `.tag` 组件，新状态往该组件加样式，不另造一套）。窄导航默认 100px，展开 224px，所有当前角色可访问的叶子入口始终直接可达。
- 订单工作区默认列表/详情并排核对，保留完整表格与六页签详情；选择、视图切换与导航展开不得重建筛选节点。空结果清除陈旧详情；选择变化仅播报简短提示。
- 列表页统一结构：标题与操作区 → 筛选区（查询/重置在右侧）→ 表格 → 分页；表单按钮（保存/取消）在底部右侧。
- 表单：必填项红星；校验失败指出**具体字段和原因**，禁止笼统"操作失败"。
- 危险操作（取消订单、变更金额、作废单证）：确认弹窗说明影响 + 提交中按钮 loading 防重复。
- 金额右对齐并标注币种；空数据要有"暂无记录/没有符合筛选条件的结果"提示。
- 桌面端 1280px+ 设计，不做移动端适配。
- 动效使用原生 CSS / Web Animations，常规反馈 140–280ms；图表和登录流程仅有一次短入场，不添加常驻装饰动画。必须尊重 `prefers-reduced-motion`；筛选、收起导航和专注预览不得通过重建页面丢失输入。
- 搜索仅索引当前角色可访问的本地页面/样例，支持 ⌘K / Ctrl+K、方向键、Enter、Esc；中文输入法组词期间不得导航。弹窗限定焦点并在关闭后恢复。
- 单证区保留目录、纸张与操作三个区域：宽桌面三栏；1001–1360px 将目录改为上方横向滚动条，保证纸张可读。

## 7. 完成标准（Definition of Done）

每完成一个步骤或功能，必须全部满足：

1. `node --check` 对所有改动的 JS 文件通过；
2. `index.html` 引用路径无缺失（新增文件必须登记进 index.html）；
3. 五类角色视角下相关页面渲染不报错（至少手动/脚本过一遍受影响路由）；
4. 金额勾稽未被破坏（改动涉及订单/收款/报价时必须核对）；
5. **更新 `HANDOFF.md`**：追加一条交接记录（见该文件模板），并同步"当前状态/待办"小节；
6. 若本文件中的规则因需求变更而失效，同步修订本文件。
