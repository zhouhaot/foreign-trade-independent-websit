### 五视角结论与小范围打磨

1. **业务员**：报价编辑保持一项保存任务，已有备注未被折叠丢失；非法输入不会显示 0 或不完整总额。数量/单价表头与输入框尚有水平错位：表头靠单元格右侧，固定宽输入容器靠左侧；建议只将报价数字输入容器靠右，保持表头、值及数字扫描线一致，不改变全站表格或字号。
2. **财务**：订单身份、随单币种、实时未收以及总/已/未收勾稽可见，失败保留完整输入。金额输入常态尚未通过 aria-describedby 关联 p-out-hint；建议关联实时额度，错误时追加 cause 而非覆盖原有 hint，减少仅凭视觉才能获得额度的差异。
3. **主管**：这批截图只有业务员/财务身份，不能据此认领主管只读或客户确认流程已通过。界面保留任务边界，未从图中看到新增确认门禁；主管、报价确认/生成及财务异常权限仍以最后路由与实际交互材料补证。
4. **键盘用户**：代码回读确认数量/单价分别有“第 n 行数量/单价”名称，常见单字段错误由 U.fieldError 设置 aria-invalid 和具名 error 的 aria-describedby，并将 focus 移至该字段；因此并非只有颜色提示。最小语义修正：报价编号/客户/业务员只读输入没有 id，U.formItem 无法生成 for，应补唯一 id；数量×单价精度错误目前只指向 price，应让该行 qty 与 price 都关联同一份错误，保留单一可见 cause，焦点仍可放 price。真实键盘、焦点返回与读屏播报尚未由本代理测试。
5. **真实性**：真实图体现原文保留、币种独立与非法金额待修正，界面没有声称退款已登记。独立数值与综合审查报告已读取：派生金额无损回查 HIGH/一项 MEDIUM、同账号新会话一项 MEDIUM 均 Resolved，两个报告为 APPROVE；这些来自独立 Node/代码审查，不等于本代理运行浏览器或证明生产入账。

### 必要语义规格与可访问树

此处是中枢实现建议，尚非已落地运行代码；唯一 id 和错误关联均需根据当前行动态形成。

```html
<label for="qe-customer">客户</label>
<input id="qe-customer" readonly value="东方之星公司（Orient Star Ltd）">
<input id="qe-qty-0" aria-label="第 1 行数量"
       aria-invalid="true" aria-describedby="qe-number-help qe-price-0-error">
<input id="qe-price-0" aria-label="第 1 行单价"
       aria-invalid="true" aria-describedby="qe-number-help qe-price-0-error">
<div id="qe-price-0-error">第 1 行数量与单价的乘积须精确到分，请调整数量或单价。</div>
<input id="p-amount" aria-describedby="p-out-hint p-amount-error">
```

数量×单价联合错误只引用一份 cause，避免重复可见长文增高；单一字段非法时只将对应字段标为无效。金额 hint 始终来自当前选择订单的实时未收。修改/清错时恢复基本 hint，并移除失效 error 引用。建议的可访问树为：具名只读报价身份 → 具名条款 → 第 n 行数量/单价及其提示/错误 → 行金额/全单合计 → 保存；财务则为选择订单 → 收款金额及当前未收/错误 → 随单币种 → 收款方式/日期/备注 → 勾稽汇总 → 登记 → 历史记录。这里描述的是预期语义，不声称真实读屏输出。
