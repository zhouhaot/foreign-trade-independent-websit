# A 方案实施规格（2026-10-07）

基准：`.impeccable/mocks/decision/modern-multicolor/a.png`；本轮用户确认先实现 A 方案前端。现有业务、角色、数据范围和静态运行约束继续有效。

## Task model / 任务层级

- Primary task：在订单工作区选择一笔订单，同屏核对订单、单证、收款三条独立进度。
- Secondary：筛选订单、进入完整详情，按角色进入相关单证或收款工作。
- Low-frequency：切换完整表格、展开高级筛选、展开导航。
- Rare：查看异常申请与历史记录，走既有详情页与审核页面。

## User flow / 用户流程

选择演示角色 → 工作台 → 订单工作区 → 筛选与选择订单 → 核对三条进度 → 完整详情／角色允许的相关业务。报价确认后才能生成订单；单证与收款是并行支线。

| 信息项 | Role / 分类 | 频率 | 首屏必须 | 阶段／显示条件 | 容器 | 可收合 |
|---|---|---|---|---|---|---|
| 订单选择、编号、客户、金额、三状态 | action-critical | 高 | 是 | 有匹配结果 | 左列列表 | 否 |
| 所选订单三条进度、已收未收 | decision-supporting | 高 | 是 | 所选记录仍在当前页 | 右列核对面板 | 否 |
| 基本筛选与结果数量 | status-feedback | 高 | 是 | 订单工作区 | 列表上方 | 否 |
| 业务员、日期、收款高级筛选 | reference | 中 | 否 | 点击更多筛选或已生效筛选 | 原高级筛选区 | 是 |
| 全部业务字段 | reference | 中 | 否 | 表格视图或完整详情 | 原完整表格／六页签详情 | 是 |

## State model / 状态模型

| 状态 | 进入条件 | Must-see-now | 隐藏信息 | 主 CTA | 离开条件 |
|---|---|---|---|---|---|
| 有结果 | 筛选后至少一笔 | 当前页订单、所选订单三进度 | 其他订单详情 | 查看完整订单 | 切换记录、筛选或打开详情 |
| 无结果 | 当前页没有订单 | 明确空态、筛选控件 | 陈旧所选详情与相关按钮 | 重置筛选 | 筛选恢复结果 |
| 表格 | 用户选表格视图 | 全部原始列、分页 | 分栏核对面板 | 查看订单 | 切回协同视图 |
| 待审核／部分收款 | 对应业务状态 | 橙色文字标签与独立进度 | 无权限业务动作 | 查看单证／登记收款，按角色 | 进入既有业务页 |
| 取消申请／已取消 | 对应订单状态 | 明确状态，未来节点不标完成 | 不适用的后续动作 | 查看订单 | 既有审核流程 |

## Tokens / 组件规范

珍珠白工作区，鸢尾紫主操作与当前订单，薄荷青收款面板。成功绿、待处理橙、异常红保持业务含义。状态始终有文字；金额右对齐并标注币种；未来流程节点保持灰色。浅导航默认窄栏，所有叶子菜单直接可达，展开后展示分组。

选择订单、切换视图、导航展开仅局部更新 DOM，保留未提交筛选输入。控件具备 hover、active、focus、disabled 状态；沿用既有键盘搜索、弹窗焦点及减少动效机制。支持 1280px+ 桌面，较窄桌面分栏纵向排列，不新增移动端业务承诺。

## 验收与 anti-pattern

禁止只换颜色而保留与 A 不符的订单工作区；禁止从图中复制三行样例而删除完整数据；禁止按图像反推角色权限、业务状态、金额或未来完成节点。保留完整表格、分页、筛选及六页签详情。
