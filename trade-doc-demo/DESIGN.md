# Design System: 外贸订单与单证管理系统（前端 Demo）


## 第7轮 PL包装核对与完整送审

PL主任务是制单员核对包装五项、保存合法待补进度、补齐送审；版本/退回意见/来源帮助作业，长冻结规则和历史后置。A字号/纸张与右栏主动作保持，1280正常目录横排、1440三栏；不把五项包装强挤纸张首屏。CI保持唛头备注具名编辑，不出现PL包装控件或隐藏完整度门槛。

H18是可撤销原型假设：件数普通正安全整数；重量明确KG/KGS、体积CBM，普通正数最多3位小数、标准千分逗号，毛重≥净重可相等。草稿允许空待补但任意已填非法拒绝；送审五项完整。合法单位/大小写/逗号/末尾0只trim首尾后保持；不自动转换单位、不从商品数量推包装、不用空当0，不改H12交易2位精度。包装方式需有实际可见文字，检查副本不洗多语言原文；实际单位/容差与货物匹配仍需人工核定。

每个包装输入具名中文+对应英文、单位hint、唯一error关联；CI/PL唛头备注也具名。毛净关系两字段同中性cause、摘要去重，数值表格错误完整正常折行；首错可见且失败保原文/dirty。已保存完整度明确限定“已保存”，编辑仍待核对；部分已保存毛重显示待补且具体缺项可读，原单证退回/制作状态不被改成假完成。失败Toast区分“包装未保存”和“本次未送审”，不抹已保存进度。

一次送审确认显示当前PL/no/Vn、编辑候选或已保存来源及五项原单位文本；成功才待审核/留痕/clean。当前合法完整输入不等真实测量或已签发。修订继承原交易与包装、重制按当前交易捕获但复制包装仍需核对；原历史审核事实/纸张保留，旧版本只读与当前导出演示资格分开。编辑完整控件、原源地址/节点/actor/候选在动作提交重验是实现保护，不向产品作业加确认门禁。

正常PL两宽scroll0/1000高保存与送审bottom约679.97/725.97（1280）、546.97/592.97（1440）；CI1440保存468.98/送审514.98。错误492/部分502/缺项451、候选确认669等实际自然滚态不称首屏0；错误扩高与纸张下部可以纵滚。readonly两张登录Toast盖低层参考、主动作不盖，不能称全部参考无遮挡。待审核纸张沿旧退回者Approved by姓名为后续签署展示风险，本轮不洗历史或认定真实签署。

## 第8轮纸张当前审核与历史事实

H19仅修当前查看CI/PL纸张审核表达：草稿/制作中未送审，待审等待本次审核，退回未通过；这些状态不填旧处理人作Approved by。当前版本已通过才显示本版本原审核姓名/章，旧已通过或取消两态仍保原事实，历史只读/暂停导出在原操作区说明。没有新增历史说明卡或动作门禁，不清旧姓名/日期/意见/history/快照，不扩签发或电子签名。

缺可见姓名保持本版已通过事实并写审核记录待核对；有名缺可见日期保名提示日期待核对。未知状态/横幅明确待核对，不默认制作中或已通过。可见性只在检查副本排White_Space/Default_Ignorable/Cc，实际原记录/合法多语言姓名保持并转义输出；不作姓名身份或日期格式/有效性认证。原空Authorized Signature线是模板，不加真实已签/未签承诺。

paper-review-status宽220px/max-width100%，paper-review-note最多220px，两者line-height1.6、white-space normal、overflow-wrap anywhere。新双语状态自然两行，签字线随内容下移不固定裁高；正常已通过原组不套statusCSS，原姓名/章与纸张交易布局保留。CI/PL两宽正常页首主动作保持，footer须自然滚动实读，不以底部滚态声称首屏0。成功/登录Toast有时在低层角落，当前审核行/主动作不盖，仍不称全参考无遮挡。

## Overview

**Creative North Star: "A · 订单协同工作区"**

2026-10-07 落地用户已确认的 A「珍珠白／鸢尾紫／薄荷青」，以 `.impeccable/mocks/decision/modern-multicolor/a.png` 为视觉基准。继续借鉴 Tabler 的布局与留白、Ant Design Pro 的筛选与业务表格、Metronic 的信息分组，形成一套本地组件。浅紫导航、紫色主操作、珍珠白工作区与薄荷青收款阅读面承载五角色；不引入模板代码、品牌资产或依赖。

订单工作区以选择当前订单、同屏核对三类独立进度为唯一主任务，保留完整表格作为另一种阅读方式。工作台压缩概览，优先展示近期订单与角色待办；审核页面并置文书与操作。界面使用简体中文，单证字段保留外贸英文惯例；动效表达进入、切换、选择与反馈，不延迟业务操作。任务层级、状态模型、信息架构与延后揭露规则见 `A-IMPLEMENTATION.md`。

**Key Characteristics:**

- 默认 100px 浅紫窄导航保留图标与名称，展开为 224px，角色叶子入口直接可达。
- 白色平面面板、细边框和适度留白承载高频业务信息。
- 筛选、分栏订单核对、完整表格与本地快速检索形成连续的查询工作流。
- 三类订单进度独立展示，单证纸张与权限相关操作同时可见。
- 状态用文字与颜色共同表达，金额携带币种并右对齐。
- 键盘焦点、字段反馈与减少动效设置贯穿共享交互。

2026-10-07 按 `css/base.css`、`css/layout.css`、`css/pages.css` 的最终覆盖规则，以及 `js/app.js`、`js/utils.js`、各 `views-*.js` 刷新本文。范围为登录、共享框架、订单工作区和现有全部模块；本文描述实现与设计约束，浏览器和业务验收结果以 `HANDOFF.md` 对应记录为准，不由文档更新推定。

## Colors

鸢尾紫承担行动与当前定位，浅紫构成导航背景，珍珠白与白色组织阅读面，薄荷青辅助识别收款阅读区；状态色承担业务含义。精确值以上方 frontmatter 为准；`blue-bg` 保留旧 token 名以兼容组件，但实际值为浅紫。

### Primary

- 鸢尾紫（primary）：主按钮、链接、当前页签、选中导航、所选订单抬头与进度当前节点。
- 深鸢尾紫（primary-dark）：主按钮 hover 与登录流程子块。
- 浅鸢尾紫（blue-bg）：当前状态标签、选中控制、单证目录选中项与单证阅读区。
- 导航浅紫（nav-bg / nav-bg-deep）：侧栏背景与非选中导航 hover。
- 薄荷青（mint / mint-bg）：收款进度条与收款阅读区，不等同于结清或审批通过。

### Neutral

- 工作区灰（bg）与面板白（card）：背景、面板和控件形成清晰分层。
- 轻分隔线（border）与控件描边（border-control）：面板边界、表格分隔、输入与次按钮边界。
- 正文深灰（text）与辅助灰（text-sub）：主要内容、字段标签、时间和补充说明。
- 中性状态底（gray-bg）：未开始、草稿等中性标签。

### Semantic Status

- 成功绿与浅绿底（green / green-bg）：通过、完成与结清。
- 待处理橙与浅橙底（orange / orange-bg）：待处理与部分收款。
- 异常红与浅红底（red / red-bg）：异常、退回、危险操作和字段错误。
- 提示紫与浅紫底（purple / purple-bg）：改价申请等类别标签，与主色共用 token，不创建第二套紫色。

**The 状态双标识 Rule.** 每个状态必须有可读文字；颜色和圆点只能辅助识别。

## Typography

**Body Font:** 系统中文字体栈；所有应用界面使用 frontmatter 中的同一字体来源，无外部字体资源。

页面标题、分区标题、业务字段与辅助信息分级；数字使用等宽数字特性方便比较。登录流程说明使用较大的同源字体，文书保留独立的紧凑排版，不把登录大标题带入业务表格。

### Hierarchy

- Headline：常规页面标题；工作台标题字距为（-.02em），订单抬头为（25px / 600）。
- Title：普通面板标题；工作台主列标题为（16px / 600），侧列与表格工具栏标题为（14px / 600），弹窗标题为（18px / 600）。
- Body：应用基准正文；表格、控件与多数业务字段采用（13px）。
- Control：按钮文本；输入文本沿用同字号而保持常规字重。
- Label：辅助标签、状态文字、日期与月份图标签。
- Metric：工作台数字（27px）；统计概览普通数值为（30px），分币种金额为（18px），订单金额摘要为（22px），较窄桌面为（20px）。
- Login Display / Login Title：分别用于登录左侧流程说明与右侧表单标题；业务页面不使用该层级。
- 单证纸张：正文（12.5px / 1.55），主标题（19px / 700），表格明细（12px）；所有内容保持真实表格和可选择文字。

**The 金额可比较 Rule.** 金额右对齐并携带币种，使用 `font-variant-numeric: tabular-nums`；不同币种不能合成一个总数。

## Layout

面向（1280px+）桌面。浅紫侧栏默认收起为（100px），展开为（224px），顶栏与侧栏品牌区均高（76px）；侧栏和顶栏保持 sticky。窄栏保留文字与图标，所有当前角色可访问的叶子菜单直接可达，展开后显示分组。工作区内边距为（30px 32px 48px），顶栏下是最小高（46px）的角色业务路径。

顶栏身份区采用（34px）紫色圆形缩写头像与账号单行组合，如 `ZJG` 头像旁显示 `zhoujg`。个人缩写为姓名拼音首字母，系统管理员使用 `ADM`；资料按用户 ID 从本地样例读取，不从登录输入推导账号。完整姓名保留在悬停提示和无障碍标签中。当前角色以只读文字独立显示，不提供直接角色切换；“退出登录”为唯一账号退出入口。身份区不再重复展示姓名、角色与部门。

使用其他账号时必须先退出再重新登录。确认退出说明未保存输入将清除、已提交演示数据保留到刷新前；取消不改变会话，确认后关闭弹窗、清除本地演示会话及页面临时状态，仅保留导航收起偏好，立即回到登录页。后退或直达受限路由仍需登录；已有会话直接访问登录路由则回工作台。该交互符合账号切换路径，但仍是假登录，不是服务端安全边界。

主要节奏使用 frontmatter 的间距级别；常规卡片内边距（20px 22px）、下间隔（16px），标题与内容间隔（24px）。工作台主列间距（24px）、侧列（20px），四项指标并为一条摘要带，以细竖线分隔。用边框、对齐和留白分区。

工作台由欢迎区、四项指标和“弹性主列 +（300px）侧列”组成。指标带最小高（110px），数值（27px），首项指标以浅紫底与紫色数字强调，各项数值/入口随角色变化。主列先展示近期订单，再展示待办；管理员将近期订单替换为演示账号。侧列包含业务入口、按完整年月标注的样例订单横条与最近动态，管理员不显示业务动态。

| 角色 | 业务路径 | 工作台关注点 |
|---|---|---|
| 外贸业务员 | 客户 → 询盘 → 报价确认 → 订单执行 | 跟进、报价确认、本人执行中订单 |
| 单证员 | 订单数据 → 单证制作与送审 → 异常申请 | 制作、退回修订、已通过版本 |

登录页采用鸢尾紫流程说明与珍珠白表单背景双列：左列说明确认报价生成订单以及单证/收款并行关系，右列表单白色面板最大宽（470px），内边距（36px），圆角（12px）；原生输入与按钮留在白色操作区。五角色使用与账号、密码同宽的原生下拉框；选项显示角色与演示姓名，下方显示所选演示部门。

订单工作区默认双栏：左侧筛选、订单选择与分页；右侧所选订单抬头、客户/报价来源、三类独立进度与相关操作。两列等宽，列间距（20px）；左列订单列表最高（510px），在自身容器滚动并预留滚动条空间；标题显示当前页实际笔数，超过三笔提示“向下滚动查看”。右列在顶栏下（96px）定位。基本筛选三列，操作位于其下方右侧；高级筛选展开两列并显示可读摘要。协同视图／表格视图切换保留未提交输入，表格视图保留九个原始列、紧凑行距和分页，内容最小宽（1040px），只在表格容器内横向滚动。无结果时同时清空右侧陈旧订单，显示调整或重置提示。

第 2 轮仅减少订单工作区留白：顶部 padding（22px）、标题区下间隔（12px）、辅助英文下间隔（4px）、视图条下间隔（10px）。筛选区 padding（16px 20px）；当前订单抬头（18px 22px）、客户来源区（12px 20px）；三进度容器 padding（12px）、gap（10px），各进度区 padding（14px 16px）、标题下间隔（16px）、收款金额上间隔（14px）；角色操作区（6px 16px 12px）、脚注底间隔（12px）。业务字号、按钮高度和完整字段继续保留；常见操作进入 1000px 高首屏的结果须由本轮真实 DOM 位置与截图验证，不由 CSS 数值推定。长名称/异常说明和高级筛选允许自然滚动。本轮最终实测常规订单动作bottom：1280×1000为968.44px，1440×1000为971.83px；具体证据见 `.impeccable/review/round-02/design-review.md`。

订单详情头部先展示编号、客户与操作，再展示金额摘要和三类独立进度，下方用六个页签分组。单证审核采用（184px）目录 + 弹性纸张区域 +（232px）操作区，列间距（16px）；专注预览可隐藏目录。纸张保留最小可读宽度（640px）与基准宽度（760px），窄列在预览容器内滚动。

在（1360px）以下保持（100px）窄导航或（224px）展开导航，工作区改为（28px 24px 40px），工作台侧列为（250px）。单证页在（1001–1360px）将目录移至上方可横向滚动的一整行，每项宽（184px），下方使用“弹性纸张 +（210px）操作区”两列，为（1280px）窗口保留纸张阅读空间，不缩小正文；较宽桌面继续三栏。

（1180px）以下通用表单折为两列；（1150px）以下顶栏搜索收为图标；（1100px）以下订单双栏纵向排列、核对面板取消 sticky、订单列表最高（430px）；（1000px）以下工作台主侧列堆叠、单证操作区下移；（900px）以下登录改单列，默认窄导航继续显示文字。这些是窄窗口保底，不构成移动端交付承诺。

## Elevation & Depth

业务面板平面静置，靠白底、细边框和留白分区，不为普通卡片增加阴影。纸张在灰色预览台上形成可识别文档实体；弹窗、通知和下拉菜单使用现有阴影表达浮层。不要把这些浮层阴影迁移到所有业务卡片。

### Shadow Vocabulary

- 纸张：`0 4px 18px rgba(20,28,48,.12)`。
- 弹窗：`0 24px 80px rgba(13,30,56,.2)`；遮罩为 `rgba(12,28,52,.42)`。
- Toast：`0 8px 32px rgba(13,30,56,.16)`，位于右下角（24px）边距。
- 通知下拉：`0 16px 48px rgba(20,42,70,.2)`。
- 输入聚焦：`0 0 0 2px rgba(101,66,217,.16)`，属于操作反馈，不是面板层级。

**The 平面面板 Rule.** 普通业务面板以边框和留白划分；阴影用于纸张与实际浮层。

## Shapes

面板、标准控件、状态标签与弹窗分别采用 frontmatter 的圆角级别。标准按钮、输入和选择器高（38px）；小按钮（30px），图标按钮（36px），分页按钮（32px）。登录输入与角色下拉框均为（46px），提交按钮为（48px）。

纸张保持矩形，商品明细使用真实表格边线。可编辑的单证字段采用紫色虚线边界提示允许编辑范围；只读字段保持文本或浅底输入，不增加装饰性立体效果。

## Components

### Buttons

主操作清楚，辅助操作克制。主按钮使用鸢尾紫；次按钮白底与控件描边；危险按钮采用红色描边，hover 为红底；审核通过按钮使用成功绿（#187b45），hover 使用（#1c7f48），白字对比实算分别为（5.31:1）与（5.03:1）。文字按钮用于低层级辅助动作。

标准按钮横向内边距（15px），图标与文字间距（6px），颜色与按压过渡（140ms）；按下时下移（1px）。主按钮 hover 转为深鸢尾紫，次按钮转为鸢尾紫描边与文字。全局 `focus-visible` 使用（2px）鸢尾紫轮廓与（3px）偏移；禁用态降低透明度并阻止操作，提交中防止重复触发。

### Inputs / Fields

白底、控件描边、标准控件圆角与高度；横向内边距（10px）。聚焦时使用鸢尾紫边框与浅紫 focus ring。必填项有红星，错误提示指出具体字段和原因；错误描边用异常红。订单带入的交易字段遵循角色只读限制。

字段标签关联输入；验证失败设置 `aria-invalid` 和错误描述关联，并聚焦首个错误。只读字段使用文本或浅底，不混同可编辑控件。

### Navigation

浅紫侧栏上的辅助灰文字与本地 SVG 线性图标；选中项用鸢尾紫和白字，hover 使用较深浅紫底与紫色文字。展开导航菜单行内边距（12px 14px），字号（13px）；分组标题为（11px）。当前项使用 `aria-current`，展开控件使用 `aria-expanded`；折叠保留角色过滤与可见文字名称，窄栏每项最小高（72px），图标（23px），不依赖悬停提示识别。业务路径只是导航，不能把单证与收款的并行流程改成串行门禁。

### Tags

统一使用现有状态组件：浅语义色底、对应文字色、左侧（5px）同色圆点，高度（25px），横向内边距（9px）。状态、类别与版本保持文字表达；不要以单独彩点替代状态名称。

### Cards / Containers

白底、轻边框、Panel 圆角。工作台数字卡 hover 改变底色与边框，首项采用浅紫阅读面，不增加升降位移。表格工具栏、表格、分页构成连续面板，不逐段增加阴影。

系统管理中的用户表和角色权限矩阵使用专用表格卡片：外层内边距为（0），内部表格容器外边距为（0），取消内部重复边框和圆角，由外层保留边界与裁切。普通内容卡片保持原有内边距。

### Filters / Tables / Tabs

订单列表提供基本筛选、更多筛选、重置和查询；高级区展开有分隔线。工具栏显示记录数量和紧凑行距状态。表头浅灰底、内边距（14px 16px），默认单元格（16px）；订单表横向（12px），紧凑行纵向（9px）。辅助字段降低颜色层级。页签为浅灰紫连体底座上的白色选中段，以文字和背景共同表示当前页。

财务与审核表格的日期、时间和人员列保持单行，日期同时使用等宽数字。表格中的普通次级小按钮使用透明底、轻描边，悬停使用浅紫底；此规则排除主操作、成功与危险按钮，保留其各自语义色。

### 登录角色下拉框 / 快速检索

“演示角色”标签关联原生 `select#login-role`，包含五个“角色 · 姓名”选项；姓名与角色相同的管理员选项去重显示。下方 `aria-live` 更新“演示部门”，并通过 `aria-describedby` 与选择器关联。选择遵循浏览器原生键盘行为，切换保留账号和密码输入；提交中禁用下拉框，账号或密码输入内 Enter 登录保持不变。

角色下拉框与登录输入使用相同背景、边框（#8b809f）、圆角和（14px）字号；左右基础内边距（14px），右侧留出（44px）容纳装饰箭头。悬停与聚焦边框为鸢尾紫、白底与既有焦点环；禁用态透明度（.55）。右侧（16px）SVG chevron 旋转（90deg）朝下，仅作提示，设置 `aria-hidden` 和 `pointer-events:none`。

顶栏按钮或 `⌘/Ctrl K` 打开本地检索，最多展示（9）项当前角色可访问的页面、订单、单证及业务员客户。输入使用 `combobox`，结果使用 `listbox/option` 与活动后代关联；上下方向键循环选择，Enter 打开，Esc 关闭；无结果时保留提示和可继续输入的焦点。不发送网络请求。

### Dialog / Feedback / Motion

审批失败弹窗保留完整规则、目标/候选金额、差额与“不改变数据”说明，内联错误使用alert；Toast仅提示“审批未生效，请查看弹窗中的处理说明。”，避免重复长文与遮挡动作。失败后保留弹窗以便修改或取消，本轮实测ToastTop922.5px、modalFooterBottom879.8px，无重叠。

共享弹窗使用具名 `dialog` 和 `aria-modal`；打开后主体 `inert`、页面停止滚动，焦点进入首个字段或关闭按钮。Tab/Shift+Tab 限定在可见可用控件之间，Esc 关闭；关闭时恢复背景和仍存在的触发元素焦点。危险操作在确认框内说明影响。键盘委托遇到 `isComposing` 或键码（229）立即返回，中文输入法选词不会误触发快捷键、搜索跳转或登录提交。

### 独立订单进度与纸张审核

订单详情保留三块并列进度；订单分栏核对面板使用三个纵向阅读区，订单白底、单证浅紫底、收款薄荷青底，各自保留标题与状态。订单和单证使用步骤条，收款使用金额、比例和状态文字。它们是并行业务信息，不生成一个合并总进度。

单证标题包含类型、编号、版本与状态，纸张上方显示当前审核反馈和只读/编辑说明；右侧按单据信息、制单或审核、导出分组。主管不能自制自审，管理员无业务审批权；已通过单证修改生成新版本。视觉精修不能绕过这些已有约束。

只读交易数据、可编辑的唛头/包装/备注和英文文书字段保持不同视觉身份。专注预览与侧栏收起不重建当前编辑表单。收款按订单币种展示，统计金额按币种分列。

### 第 2 轮单证阶段与交易来源

订单分栏与完整详情共用 `documentStages(o)`。阶段文字为“制作 → 送审 → 审核 → 可导出”，真实 `docStatus` 标签继续显示，两者不能互相替代。仅取商业发票 CI 和装箱单 PL 各自最高版本；旧版退回不覆盖新版已通过。两类最新单证均已送审且无退回时，才把制作、送审画完成勾；仅一类送审为紫色虚线圆点的部分进度。含退回时制作为异常、送审为部分进度，不保留制作/送审完成勾，旁注改为“曾送审”并说明修订后重新送审。审核在两类均通过时完成，待审核/退回使用橙色当前或异常标识。无单证四节点中性，附“尚未制作单证”。

可导出在两类最新单证均通过且订单不处于取消申请中/已取消时使用绿色边界与箭头表达条件就绪，**不使用完成勾，不写“已实际导出”**。这只是资格；实际动作和权限仍由现有单证页处理，导出仍为演示。阶段旁注显示最新单证数量、已送审类数和待审/退回情况；订单、单证、收款仍是独立信息，取消不能抹去既有单证/收款事实。已取消订单保留实际审核事实，但第四节点为中性，并说明单证操作与导出暂停；取消申请中在分栏与完整详情均显示中性订单阶段及暂停说明。

单证页“交易数据来源”区常显“样例基线·非历史签发记录”或“创建时交易快照”，并常显北京时间；原生 details/summary“查看冻结规则”默认收起长解释。展开后明确初始 Demo 版本为本次页面加载时冻结的样例基线，无法还原历史签发数据；新建快照说明来自捕获时的订单与主数据。冻结时间从版本快照取值，并明确按北京时间显示，原 ISO 时间保留提示。包装、唛头、备注受控修订沿用原交易快照与冻结时间；经审批重新制单捕获当时当前交易。两种创建路径在按钮/确认提示中分别说明，旧版本保持原交易内容。

文书阶段容器使用 role=list，每节点 role=listitem，装饰标记 aria-hidden；每个阶段补 sr-only 状态文字，使用单一 aria-current=step 标识当前阶段。部分、异常、条件尚未满足和可导出资格均能从文字区分；ready/warn 标签使用正文色，保留圆点/箭头语义色，避免浅紫底上的低对比小字。该结构经代码复核，真实读屏效果仍须独立验证。

## Usage / 使用场景

协同视图适合业务主管、业务员、单证员和财务逐笔核对并进入下一步工作；表格视图适合横向比较客户、业务员、来源报价及创建时间。系统管理员以配置管理为主，不因公共视觉而获得业务审批入口。订单工作区先处理一笔订单，再展开低频筛选、完整字段或历史记录；详细任务和状态约定见 `A-IMPLEMENTATION.md`。

## Anatomy / 订单工作区组成

左列连续面板包含基本筛选、可展开高级筛选、订单选择按钮及分页；每笔按钮包含编号/金额、客户、业务员/日期、三个文字状态。右列包含紫色当前订单抬头、客户与来源报价、订单/单证/收款三个进度区及角色允许的操作。全宽视图切换栏属于两种阅读方式的共享控制，不与某笔业务操作混淆。

## States / 状态规范

| 状态 | 可见表达 | 操作约束 |
|---|---|---|
| 默认与悬停 | 白底或浅语义底，hover 使用浅紫；主操作 hover 深紫 | 悬停不改变所选订单、不发送业务写入 |
| 已选中 | 左侧紫色边标、浅紫底、按钮 pressed=true；右侧编号同步 | 不自动跳转详情，保留选择按钮焦点 |
| 聚焦 | 2px 紫色轮廓与3px偏移；列表按钮内缩以免裁切 | 键盘焦点与业务选中态独立，不能只靠 hover |
| 禁用与提交中 | 禁用文字、透明度和 loading；保留原因说明 | 防重复提交，完成动效不视为业务成功 |
| 空结果 | 左侧明确无匹配记录，右侧无可查看订单 | 移除旧订单与相关动作，允许调整/重置筛选 |
| 退回与取消申请 | 明确橙/红文字标签和原因提示，未来节点不标完成 | 沿用既有修订/审批规则，不按配色推导业务权限 |

## Interaction / A 方案操作与可访问性约定

订单选择使用原生按钮，`aria-pressed` 表示当前选中记录，`aria-controls` 关联右侧订单核对面板。操作后保留列表按钮焦点，不把焦点自动移到右栏；用独立 `role="status"` 区域简短播报所选订单编号，避免把整个三进度面板设为 live region 而反复朗读金额。视图切换按钮沿用 `aria-pressed`，隐藏视图使用 `hidden`，不能把不可见控件留在 Tab 顺序。

预期无障碍树：主导航 → 当前页链接；订单工作区标题 → 已关联标签的筛选字段 → 协同/表格视图按钮 → 订单选择区域及每笔订单按钮（编号、金额、客户、订单/单证/收款文字状态、选中态）→ 所选订单进度区域（三个具名分区）→ 收款比例进度条（0–100 的数值）→ 当前角色可执行的业务链接。登录角色仍是具名原生选择器，演示部门变化轻声播报。该描述是语义实现目标，不代替真实读屏测试。

焦点顺序遵循 DOM 的业务阅读顺序。Tab 可到达筛选、切换按钮、每笔订单和相关操作；Enter/Space 选择订单；全局搜索、弹窗及退出确认沿用现有焦点管理。文字按钮也至少保留（24px）高的点击区域；状态标签仅作信息，不伪装为可点击控件。控件边框（#8b809f）与白底实算对比为（3.69:1），与（#faf9fd）为（3.52:1）；面板分隔（border）保持浅色，不承担控件识别。

## Do's and Don'ts

### Do:

- Do 沿用浅紫导航、鸢尾紫主操作、珍珠白工作区、薄荷青收款阅读面与系统中文字体。
- Do 用角色概览、近期订单与待办接续工作，单证页面让纸张与业务操作并置。
- Do 用角色与业务状态决定可用动作，让只读、退回、错误和禁用原因可读。
- Do 将金额右对齐并保留币种，月份标签保留年份。
- Do 保持普通 HTML/CSS/JS、file://、本地 SVG 与全局 data-action 委托。
- Do 保留可见键盘焦点、中文输入法保护和减少动效下的完整操作能力。

### Don't:

- Don't 因参考模板使用框架而引入框架、构建工具、CDN、外部字体或图片。
- Don't 合并订单、单证、收款状态，或在订单列表增加直接新建订单。
- Don't 用颜色替代状态文字，或用不明原因的灰色控件替代权限说明。
- Don't 持久化业务写入或把假登录、假分页、导出演示描述为真实后台功能；业务数据刷新后还原。
- Don't 把代码实现、设计规范或静态检查通过写成浏览器、全业务或生产验收通过。
