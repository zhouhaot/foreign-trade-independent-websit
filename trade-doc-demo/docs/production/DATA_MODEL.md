# 首个业务切片数据模型

本切片覆盖认证、共享商品、本人客户与询盘、报价确认及首次成单。字段和约束的机器可读来源为[slice-01.data-model.json](slice-01.data-model.json)。这是引擎中立的逻辑设计，不是已执行的DDL，也不是已经通过数据库事务测试的实现。

## 已确认与设计候选

需求方已确认服务器部署、业务员只看本人负责业务/主管全量、只录新业务、公司商品共用、确认附件可选，以及数量/单价各最多两位且行金额必须精确到分。客户确认方式、日期和说明必须记录。

UUID主键、DECIMAL(20,2)、同源Cookie会话、单一有效岗位、Asia/Shanghai业务时区是本切片的工程候选，实施前通过架构决策锁定。数据库产品、依赖版本、流水编号、报价过期后的例外、报价修订、账号兼岗、订单后续状态推进仍未批准。旧草案“未回复按建议默认”不能替代本次确认。

## 表与关系

| 表 | 用途与关键关系 |
|---|---|
| app_user | 稳定人员ID、登录名、密码编码、岗位、启用状态和权限版本；不导入Demo用户 |
| user_session | 服务端会话索引、过期/撤销及认证版本；不向业务接口返回敏感字段 |
| currency_catalog | 公司批准的启用币种及金额精度；首切片只接受两位金额币种，无自动换汇 |
| company_profile | 真实本公司抬头与版本；未配置不能提交报价，不默认使用演示出口方 |
| product | 公司共用商品，SKU唯一；引用后不提供删除接口 |
| customer | owner_user_id由真实登录身份生成；客户资料变更不改历史交易 |
| inquiry | 客户与业务员一致的复合外键；创建时检查客户端审阅的客户版本 |
| inquiry_line | 关联共用商品，捕获SKU/描述/规格/单位/版本与询价数量 |
| quote | 每询盘首份报价唯一、同归属客户、币种、条款、有效期和提交快照 |
| quote_line | 必须对应同询盘的原行；草稿按当前报价完整稳定lineNo集合修改数量/价格，不能串其他报价行 |
| quote_confirmation | 每报价一份确认，用户填业务日期/方式/说明，服务端记登记人/时间 |
| sales_order | 来源报价唯一且必须有关联确认；归属从报价继承，禁止客户端改owner |
| order_version | 首次版本V1，复制确认快照与币种/总额，另采集交货日期；本切片无修订接口 |
| order_line | 绑定同一来源报价和订单版本的原明细，版本内行号唯一 |
| idempotency_record | 同操作人+幂等键唯一，与业务事务共同提交，不保存敏感完整响应 |
| audit_event | 成功业务事件只追加，记录服务端身份/时间/版本，不开放任意改写 |

每个字段默认非空，只有逻辑模型中明确nullable的字段允许空。包含common字段的表在落库时须展开created_at/created_by/updated_at/row_version；created_by的外键同样不可漏。不可物理删除仍有引用的用户/客户/商品；停用及交接流程需单独定义，不用删除历史行代替。

## 归属与引用完整性

customer具有唯一键(id, owner_user_id)。inquiry使用(customer_id, owner_user_id)复合外键，quote再使用(inquiry_id, owner_user_id, customer_id)复合外键。这样不能仅凭客户端拼入另一个客户ID生成越权交易。还必须在服务层检查当前用户、岗位、权限和归属，外键不代替授权。

quote_line同时约束其quote和inquiry_line来自同一个inquiry。sales_order对source_quote_id全局唯一，不依赖前端防重复；它同时引用quote_confirmation，不能给未确认来源成单。order_line同时约束order_version和quote_line来自同一报价。所有这些键在数据库选型后的迁移中落实并验收，目前只是设计要求。

## 快照捕获时点

1. 创建询盘时核对productVersion，捕获商品描述快照；之后修改共用目录不自动更新该询盘。
2. 从询盘创建报价，复制商品快照与数量；报价日期由服务器生成，有效期默认+15个日历日，沿用已评审Demo。成交价由业务员填写，未填价只能保留草稿，不猜测参考价已经获接受；草稿可暂清空有效期，但提交前须补齐。
3. 草稿读取时展示当前有权访问的客户/本公司资料预览及sourceVersions。提交报价时核对expectedVersion、expectedCustomerVersion、expectedCompanyProfileVersion；来源变化返回409，要求重新审阅。
4. 提交待客户确认时一次冻结卖方、客户、商品、数量、价格、币种、条款和有效期；确认记录逐值复制此版本，不从新主数据补写。用户填写的confirmedOn与服务端recordedAt分开。
5. 成单复制确认快照。客户端只能给报价期望版本与必填交货日期，不能重传客户、明细或总额覆盖已确认内容。

## 金额与日期

API使用十进制字符串，数量和单价均为正数、最多两位。候选存储上限为18位整数+2位小数；后端必须在数据库转换前显式拒绝超范围值。

令数量和单价分别转为整数百分单位Q、P。仅当Q×P能被100整除时，该行金额的“分”为(Q×P)/100；余数非零即422并指出行，不调用round(2)掩盖差额。例如0.01×0.01拒绝，0.01×1.00得到0.01。合计同币种逐行相加并再次检查上界，不能使用JavaScript Number作为服务端结算依据。

业务日期使用真实日历日期；创建日与过期判定取服务器配置的业务时区，审计时间存UTC。暂按quoteDate≤confirmedOn≤validUntil且confirmedOn≤业务今天，并拒绝有效期已过的确认/成单；这些日期保护属于保守候选门禁，过期后允许补录或转单的正式规则需业务确认。报价有效期只是字段与校验，不从本轮推导自动定时任务。

## 本切片不包含

不发布通用订单新增/修改、报价修订、订单开始/完成/取消、单证、收款或业务日志全量查询接口。订单首次创建返回待执行、单证未开始、未收款三条独立进度；这不是订单已执行或已完成。附件可选已确认，但上传能力待后续文件安全设计，不能声称已交付。
