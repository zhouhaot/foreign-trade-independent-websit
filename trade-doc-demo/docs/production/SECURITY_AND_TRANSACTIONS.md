# 首个业务切片权限与事务契约

本契约用于实现与验收，不代表已有后端。接口定义见[slice-01.openapi.json](slice-01.openapi.json)，字段与复合键见[数据模型](DATA_MODEL.md)。正式应用与静态Demo隔离，正式身份不得来自演示角色下拉框、请求体或客户端存储。

## 首切片岗位边界

| 接口对象 | 外贸业务员 | 业务主管 | 管理员 单证员 财务 |
|---|---|---|---|
| 当前身份与退出 | 自己 | 自己 | 自己 |
| 启用币种与共享商品读取 | 公司目录 | 公司目录 | 本切片未开放销售目录接口 |
| 共享商品维护 | 具备对应权限可写，版本冲突拒绝 | 只读 | 拒绝 |
| 客户与询盘 | 本人读取/创建；客户可版本化修改 | 全部只读 | 拒绝 |
| 报价草稿及提交/确认/成单 | 本人对象、当前状态及权限均满足才可写 | 全部只读 | 拒绝 |
| 订单读取 | 本人 | 全部 | 本切片暂不开放，后续按单证/财务职责设计 |

主管全量读取不等于能代业务员写入。后续主管业务审批仍不得自审，管理员无业务审批权的规则不变。其他岗位本切片的拒权不是永久移除其业务职责，而是暂不发布相应生产能力。

## 鉴权与会话候选

- 同源HTTP应用采用服务端会话Cookie，候选名TRADE_SESSION；生产必须Secure、HttpOnly、SameSite=Lax、Path=/api/v1且不设宽泛Domain。禁止把会话令牌放URL、响应业务JSON、Git或日志。HTTPS/代理边界在部署前实测。
- GET /auth/csrf返回会话绑定的CSRF令牌并禁止缓存；POST登录和退出也必须校验X-CSRF-TOKEN。登录成功轮换会话标识及CSRF令牌，前端重新获取CSRF。Cookie鉴权不能以“内网”或“JSON请求”替代CSRF防护。[Spring CSRF说明](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)
- 登录成功后每次请求重新核查用户启用、auth_version和有效权限，停用/改凭据/撤权后旧会话不继续写；退出必须撤销服务端会话，而不只是删浏览器Cookie。会话固定防护需按选定Spring版本配置和测试。[Spring会话说明](https://docs.spring.io/spring-security/reference/servlet/authentication/session-management.html)
- 密码仅用经选型的自适应单向PasswordEncoder，参数结合目标硬件测试，不使用明文、可逆存储或裸SHA摘要；登录失败保持统一提示并限流，不区分账号不存在/禁用等细节。[密码存储说明](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html)
- 请求/方法层设置默认拒绝。归属过滤在数据查询中执行，而非查出全量后由浏览器过滤。权限及字段白名单在实际写入前重查。[方法授权说明](https://docs.spring.io/spring-security/reference/servlet/authorization/method-security.html)

账号初始化、首次密码设置/重置、会话空闲/绝对超时、限流阈值及兼岗在启动实现前锁定；本切片不创建默认生产账号或开放身份切换接口。测试只使用显式合成账号，测试配置不能随生产包启用。

## 输入与错误

所有业务写DTO拒绝未知属性，特别是ownerUserId、actorUserId、role、status、totalAmount和客户端审计时间。日期、正数、小数精度、长度、行数、字典、来源ID、状态、版本须在后端校验；JSON语法正确不代表业务合法。

| 状态码 | 用途 |
|---|---|
| 400 | JSON语法、非法查询/路径格式、缺少或格式错误的幂等请求头 |
| 401 | 未登录、会话过期/撤销、账号禁用；登录失败统一响应 |
| 403 | 已认证但岗位/操作权限不足，或CSRF不匹配 |
| 404 | 对象不存在或不属于有权范围；不得返回客户名/金额等线索 |
| 409 | 状态/乐观版本/来源资料变更、幂等键冲突、唯一性冲突 |
| 422 | 字段值、真实日历日期、非整分、超界、资料不完整等业务输入错误 |
| 429 | 登录或接口限流 |

Error包含稳定code、中文message、requestId及必需fieldErrors数组；无字段错误时为空数组，不返回堆栈、SQL或认证细节。涉及对象的字段/版本错误只能在鉴权和归属检查后返回，不能用错误差异探测其他业务员的对象。即使UUID不可猜也必须做对象级授权。列表items与total、搜索/筛选和聚合使用同一归属条件。

## 幂等与版本

除登录/退出外，每个业务写请求必传Idempotency-Key。键在同一真实操作人内跨接口唯一；请求指纹包含operationId、路径、查询及规范化业务body。对象键顺序规范化、十进制等值统一，不将密码、Cookie或CSRF放指纹输入或持久响应。客户端重试同一操作复用原键，新动作必须新键。

同键同指纹已成功时返回同一资源的当前授权表示，HTTP200并带Idempotency-Replayed:true；只保证原业务效果不重复，不保证响应字节或旧字段/版本相同。创建首次成功201，更新首次成功200。既有不可变确认/订单版本仍保持其历史内容。同键异接口/路径/内容返回409。幂等记录与业务、成功审计同一事务，失败全回滚，成功后不能因服务重启遗失防重复依据。暂不自动清理键；过期/归档策略未定义前不把旧键重新当新请求。

幂等重放前先核查当前身份/启用/权限和资源归属，不能直接回放缓存数据。重放已成功结果允许原expectedVersion，不能被本次成功导致的版本增长误判；不是幂等重放的新写入，必须严格匹配最新版本。事务内重新检查条件，返回409时不自动合并覆盖。

## 事务边界

| 动作 | 一次成功必须共同提交 |
|---|---|
| 创建商品/客户 | 合法字段、唯一性/归属、记录与版本、幂等记录、成功审计 |
| 修改商品/客户 | 角色与归属、原row_version、完整候选、row_version+1、幂等及审计 |
| 创建询盘 | 客户归属及版本、商品版本和快照、全部询盘行、父记录、幂等与审计；任一行错误全部不写 |
| 询盘起草报价 | 询盘来源/版本、复制全部行与快照、DRAFT报价、询盘QUOTED、幂等及审计；不同键并发也只能一份首报 |
| 保存报价草稿 | 同一报价的完整原行集合、精确金额、币种/条款/日期、草稿状态、原版本、全部明细及总额一起更新 |
| 提交待确认 | 原版本与来源客户/本公司预览版本、完整商品/交易候选、issued_snapshot、AWAITING_CUSTOMER、幂等及审计 |
| 登记客户确认 | 原版本/待确认状态、必填确认记录、issued_snapshot逐值复制、CONFIRMED、幂等及审计 |
| 报价成单 | 原版本/确认记录、唯一订单、V1与全部行、确认快照复制、quote.converted_at、幂等及审计 |

并发控制统一按“认证/授权上下文→幂等键占位→来源聚合根→行/依赖”固定锁序。更新草稿、提交、确认与成单必须在同一报价聚合上串行或使用等价原子版本条件，不得分别检查再无锁写。数据库选型后确定隔离级别、行锁/版本CAS、唯一冲突回读及有限重试；本轮不以伪内存事务证明真实数据库安全。

## 成单重试与竞争

首切片每询盘一份报价，每报价至多一张订单，不涉及报价修订链。不存在通用POST /orders或修改订单核心字段的接口。

成单流程先在同一有权来源报价上检查是否已有订单。若是同键成功重放，返回已有结果200；若换了新键但deliveryDate与已存V1一致，也返回同一订单200，不再创建且不重复写业务审计。若deliveryDate不同则409 SOURCE_ALREADY_CONVERTED。此读取分支可接受最初expectedVersion，因为不产生新业务写入，但必须重新鉴权；无既有订单的新写分支才检查期望版本、确认/有效期并执行创建，首次成功201。

source_quote_id数据库唯一约束为最终兜底。若两个不同键竞争同一来源，即使应用层同时判断“未成单”，也不能出现两行订单；冲突回读须再次校验原请求交期及当前授权。若变更快照、明细、关联、审计或幂等任一步失败，整个事务回滚；唯一约束异常不能直接包装为假成功。

## 交付与验证边界

本轮只检查逻辑键、OpenAPI内部引用、DTO白名单/金额类型、操作权限标记、验收映射及反例能否被静态检查器捕获。真实鉴权、CSRF、外键、并发、事务回滚、文件权限和服务重启持久化，必须由后续服务/数据库/浏览器集成用例验证，当前均未执行。验收矩阵中的PLANNED不是PASS。
