# 外贸系统首版落地实施基线

2026-10-14。阶段为生产化准备，尚未建立后端或部署生产服务。目标是公司内部可持续使用的系统，不以演示链路通过代替上线验收。

## 已确认范围

- 面向本公司内部员工，约15人；总人数与同时在线数仍需区分。
- 部署到服务器，不采用NAS作为当前目标；操作系统、CPU架构、内存、存储和容器条件待补。
- 业务员只能查看自己负责的业务，主管可查看全部。列表、详情、搜索、统计、导出及附件下载均执行相同数据范围。
- 首版从新业务录入开始，不迁移历史Excel或订单；Demo样例不得自动成为正式业务数据。
- 保留五岗位、已确认报价成单、单证与收款并行、三类进度独立、禁止自审、管理员无业务审批权、分币种金额及已审版本不覆盖等既有规则。

## 首版功能边界

沿当前已评审业务链路建设真实登录、客户和商品维护、询盘、报价与客户确认、订单、CI/PL制单审核、收款与应收、变更申请、统计和操作记录。用户与字典维护须从演示只读占位变为受控真实功能。

正式CI/PL文件导出纳入交付目标，但模板需由业务确认；先验证样本输出，不把模板视为海关、银行或法律合规认证。采购、库存、生产、银行支付、出口退税、汇兑损益、多租户和新增单证种类不在本轮默认范围。

## 与现有项目的隔离

`trade-doc-demo/`继续保留为静态评审和回归基线，不在这里直接接生产数据或移除file://能力。生产应用拟在仓库中独立目录建设，工程结构及适用规则在创建前登记。现有无后端、无构建工具约束仍约束Demo；本文件不视为向该目录加入后端的许可。

正式应用不提供选择任意身份的快捷切换，也不接受请求体传入的角色或操作人作为可信身份。后台从已认证会话识别人员，前端菜单只是可用操作的呈现。

根目录`docs/PROJECT_BRIEF.md`、`SRS.md`、`STATE_TRANSITIONS.md`和权限/字段责任表均标为旧草案。其Spring Boot模块化单体方向可作为技术候选，但Vue重写、MySQL/MyBatis、具体版本、状态联动及所有默认答案均不能因文件存在而视为已批准。

## 首个真实业务切片

先做“登录→本人客户/询盘→报价确认→生成订单→重新查询”的可持久化链路，暂不把所有模块并行铺开。

| 交付 | 必须证明的结果 |
|---|---|
| 真实账号与会话 | 用户停用后拒绝新业务操作；退出后旧会话失效；演示身份选择不能进入正式授权路径 |
| 数据归属 | 业务员A读取B的列表、详情、搜索、统计、导出均无越权；修改ID不能绕过；主管可读两人的授权业务 |
| 服务端字段校验 | 金额、来源报价、归属人、状态和审计字段由后端校验或生成，不能通过篡改JSON直接写入 |
| 报价生成订单 | 已确认来源、明细复制、快照、关联和转换标记同一事务；重复/并发请求最多一张有效订单 |
| 持久化与恢复 | 刷新与服务重启后仍可查同一订单；中途失败整体回滚，不能出现半张订单 |

数据范围不能只在Controller按角色判断；查询本身必须限定归属，统计计数和文件接口也不能泄露其他业务员的数据。服务端请求级与服务方法级授权可分层配置，Spring Security不会因引入依赖就自动启用方法授权。[官方方法授权说明](https://docs.spring.io/spring-security/reference/servlet/authorization/method-security.html)

业务唯一约束、幂等键、事务与并发控制须共同设计；“先查询余额再写收款”不足以证明并发安全。若采用MySQL，需要按真实隔离级别设计锁与失败重试，并用真实数据库验证，不用内存库结果替代。[MySQL锁定读取说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)

## 数据模型与事务设计交付

首个设计批次产出表结构、API和权限规格，不直接把前端Mock数组改成数据库表。

- 用户主键与业务归属主键采用稳定ID，姓名只用于显示；真实账号不使用Demo样例身份自动开通。
- 客户、询盘、报价和订单记录归属关系；单证和收款通过关联订单执行岗位与数据范围校验。商品共用/归属、跨岗位可办范围及人员离职交接另列规则。
- 来源报价、订单交易版本、单证版本、实际CI关联和模板版本分别建模，历史快照不随主数据修改。
- 金额、数量、币种、度量使用明确精度的十进制字段，服务端计算为准；API金额优先使用十进制字符串，避免JSON浮点往返改变数值。
- 报价转订单、首制双单、审批生效与收款登记分别定义事务边界、唯一约束、幂等语义、版本冲突和错误响应。
- 文件保存位置不等于下载授权；附件与生成单证使用受保护标识访问，审计操作者/时间来自服务端。

## 必须收敛的业务规则

数据可见范围已由本次答复确认。其余问题按实现阶段逐组确认，不要求一次回答旧清单中的全部问题：

1. 报价与订单：确认凭据是否强制附件；数量/价格/币种精度；订单开始及完成条件。
2. 单证：订单改价后旧文件何时失去正式导出资格；新修订创建还是审核通过时切换有效版；CI/PL编号及模板样式。
3. 收款与异常：已收款订单取消限制、错误收款冲销审批与退款是否首版实现；没有规则时拒绝相关动作，不猜测清账。
4. 运维：首次账号开通与重置流程、备份保留、可接受数据损失时间及恢复时间、日常运维负责人。

试运行前必须有独立数据库账户、服务端密钥管理、受限网络/TLS方案、登录与权限测试、健康检查、日志与磁盘告警。Spring Boot可提供健康与指标等运维能力，但端点的暴露范围和访问控制仍须显式设置。[官方生产运维能力](https://docs.spring.io/spring-boot/reference/actuator/index.html)
