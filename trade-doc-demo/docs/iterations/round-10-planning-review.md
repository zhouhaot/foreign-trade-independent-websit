## 推荐最小一轮与现实收益

推荐只修`oc-form`的改价申请初次金额输入：业务员首次填写非法表示，应在当前字段看到具体错误并保留原因，而不是把指数/十六进制偷偷转换成申请金额，或将三位小数以两位标题掩盖。当前单据、报价、收款和审批已具金额契约，申请入口仍走宽松Number校验；这个局部缺口有真实动作证据，收益是减少污染审批队列和主管返工。

不改取消申请、已存targetAmount、改价批准算法、H20关闭保护、交易数量精度或真实收款/退款制度；不新增后台、数据持久化、部署或审批制度。每轮仍由中枢安排多agent、多视角修正、改进说明、复盘及正常Git推送。

## 初始填写真实RED：与H20内容漂移分开

实际代码`views-sales.js`在订单变更点击处理内，以`U.validate({number:true,min:0.01})`校验金额，再用`Number(oc-amount.value)`存targetAmount。`utils.js`的通用validate只看isNaN和min，没有有限数、普通十进制、两位或安全分约束。H20保捕获后的同源节点/原始值一致，但它不决定首次填入的值是否合法，不能把“提交后A改B被拒绝”当成初值已验证。

隔离VM加载当前真实Actions、原openModal/validate/withLoading/Promise/app；每例使用原SO2026001，首次填写金额与原因，点击后不再改字段，等待实际回调完成。没有删样例申请、改订单状态或注入Mock来让表单成功：

| 首次输入 | 实际新增targetAmount | 实际申请标题金额 | 观察 |
|---|---|---|---|
| `1e3` | number 1000 | 1,000.00 USD | 指数原文静默消失 |
| `2.4e4` | number 24000 | 24,000.00 USD | 与普通24000同存，失去原始表示 |
| `0x10` | number 16 | 16.00 USD | 十六进制静默转换 |
| `Infinity` | number Infinity | ∞ USD | 真正非有限目标写入待处理申请 |
| `1e309` | number Infinity | ∞ USD | 溢出仍写入待处理申请 |
| `24000.001` | number 24000.001 | 24,000.00 USD | 标题隐藏超两位精度 |
| `9007199254740991.99` | number 9007199254740992 | 9,007,199,254,740,992.00 USD | 原值丢精度，数值已改变 |

上述7例均新增申请并程序关闭原表单，字段没有错误。金额0、-1、abc原已拒绝且输入保留，是既有安全对照；0.01、24000.00、外侧空格24000.00原能提交，是合法候选对照，不称新增功能。每例订单对象、单证和收款前后逐字不变：问题是新的待处理申请和标题，并非已经批准非法订单交易。Infinity通过String读取真实数值，不拿JSON中Infinity变null误称数据原本null。

非法原文应拒绝且不新增申请的期望断言实际失败并捕获成RED，探测程序整体退出0只说明证据收集完成，不是候选校验通过。全部是Node最小DOM/真实动作证据，还没有第10轮真实浏览器红灯、UI或修复结果。

主管端`views-fin.js`的prepareRepricing已有amountCents：非有限/超两位/安全范围目标会拒绝批准；已收下限、同币种、整数数量改价能力和候选合计等规则也已存在。本轮不能把入口污染扩大成“审批都漏校验”。指数/hex已被入口Number转换后，主管只看到规范数值，原始表示已丢；更应在新申请写入前判定，而不是回洗历史或再造金额转换。

## H-21候选：仅新改价申请金额

可撤销假设H21现已选定：新改价申请目标沿现有两位金额表示能力，仅普通正十进制、至少0.01、最多两位小数，分值为安全整数且Number保存可无损往返。它是前端演示输入口径，不证明企业正式报价金额精度、申请批准可行性或实际可交付数量；本轮不改正式制度。

优先复用既有`U.decimalInput(raw,'变更后订单金额')`的`ok/units/value/error`，它已trim外侧空格、拒指数/hex/Infinity/超精度、验证安全分与无损存值。只对oc改价分支使用，无需全局改U.validate或新建第二套金额parse。合法前导零随现有helper，逗号分组、加号、点前省略0/尾点等按当前helper明确拒绝；不自动猜地区小数符号、汇率或补精度。

- **新申请**：校验通过的value存既有number targetAmount；标题来自同一候选值，最多两位的原文不靠舍入救成合法。非法不创建申请、不加日志、不假成功，原原因/字段/错误及H20未提交保护保留。
- **取消申请**：隐藏金额不参与此契约，不因为旧隐藏金额非法而阻止取消；targetAmount仍null，原取消前状态、暂停/历史保留与审批效果不改。切回改价则校验实际保留值。
- **旧申请**：已有targetAmount/title/history原样，不迁移、不清洗、不重新解释原文。主管既有审核函数继续拒绝或批准其实际候选；未知旧金额如实由原提示处理。
- **与已收/订单的关系**：不在申请阶段新增“低于已收不得提交”的制度；0.01仍可作为合法申请数值，但主管原下限/等比两位单价合计能力可能拒绝批准。不能宣称合法输入即必然可批准、或更改单价算法去消除差额。
- **身份与异步**：继续用H20源节点/rawvalue/actor/目标/状态/币种绑定和一次提交，初值合法与后续内容稳定都必须成立；保原延迟检查和源绑定关闭。这个候选不重新设计审批锁、ID或角色权限。

企业待输入是正式金额/地区输入口径、是否应在申请前提示可批准性及改价数量制度；缺输入不阻止上述明确假设的小修，但不能擅设退款、FX、超收或新金额上限。撤销H21时仅调整后续输入规则/测试，不回写旧申请或单证快照。
