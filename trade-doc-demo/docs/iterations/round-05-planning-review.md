# 第5轮现实规划：岗位上下文与离开保护

日期2026-10-07；基线`6ffd844c097c82b6e9a4f8655dd7d1cd48aff31a`。第4轮实现与回执已推送并由中枢回读，本轮进行中。规划只写本文与路线，不修改实现、治理、历史材料或Git。

## 目标与范围

员工正在填写报价、客户资料、收款或单证内容时，全局跳转不能无声丢输入；取消离开继续原作业，确认放弃才抵达合法下一步。沿用A配色、原一次确认和各岗位权限，不增加后台、持久化或自动保存。

H-14本轮明确保护：`qe-form`报价编辑、`cust-form`客户资料、`pay-form`收款登记、单证编辑的唛头/包装/备注与`audit-opinion`审核意见。覆盖会销毁这些输入的侧栏、业务路径、品牌、搜索、铃铛、页内链接/目录、浏览器同页历史与同页重建。客户确认/订单申请/审批等通用弹窗草稿与跨页面恢复列后续；不将有限输入守卫称全站草稿管理。

H-15本轮应用内导航先确认再改URL；本轮建立的显式会话历史可可靠恢复Back/Forward方向；加载前或未知历史条目不猜方向，兜底地址/输入恢复与原历史栈完整性分开报告。两项都是可撤销原型选择，不是企业资料保存或生产浏览器支持承诺。

## 用户模型与历史最小方案

普通应用链接取消离开时应留在原URL和原DOM；不应先跳目标再重新渲染原页，否则报价token、财务表单引用、字段错误与焦点都失效。统一`App.requestNavigation`或同等入口，先检查源作业，再确认；确认前不写hash和历史。Ctrl/Meta/Shift点击或新标签页不销毁源页，应保留浏览器正常行为。

浏览器Back/Forward是先移动历史、后通知应用，不能照搬普通链接模型。建议：初始化只标当前条目，用本会话epoch、相邻条目递增1的位置索引、目标hash标记统一入口创建的条目；已接受路由与索引作为源事实。索引必须代表已知栈位置，不能用全局累计导航次数：Back后新导航裁去Forward分支，新条目为当前位置+1，否则索引差不等于真实步数。收到同epoch且hash一致的历史目标时，先保留源DOM；确认后接受并渲染目标，取消时按已知索引差`history.go`回原条目，并仅放行匹配的恢复事件。`popstate`与`hashchange`去重，一次用户动作最多一份确认。历史标记只存导航元数据，不保存表单内容。

这不是靠history.length、URL数字或旧新hash猜方向。验收必须证明：取消Back后仍在原条目；再按Back仍面对同一目标；取消Forward同样成立，没有跳过条目、循环、重复弹窗或源DOM重建。应用内部成功跳转也走统一入口，并在实际业务提交后先将源状态标干净。

未知/加载前条目没有可靠索引：可采用保源DOM、`replaceState`恢复原地址的安全兜底，但它只保证输入/地址恢复，可能改变历史栈，不能写“历史完整恢复”。实现需记录选定兜底及实际浏览器结果；若工具不能验证，明确未验证。不可盲目`history.go(1)`或`go(-1)`假设所有事件来自Back。刷新/关闭可标准`beforeunload`尽力提示，但浏览器决定是否弹提示；不自定义系统提示、不承诺恢复数据，用户确认刷新仍按Mock复位。

## 输入、动作与上下文契约

- dirty基线来自进入页面或成功提交后实际显示的字段值，不能只靠“发生过input”。恢复全部原值应回干净；无修改、只读查看、筛选/搜索/布局展开不新增离开门禁。对业务值的规范化须显式一致，不因展示格式误报。
- 取消或Esc关闭离开确认保留同一个源DOM、原输入、错误、选择与滚动。焦点回当前或最近作业字段，`focusin`记录须包括校验错误带来的字段聚焦；没有可用作业字段才回原触发控件。确认“放弃输入并离开”只清未提交内容，不写报价/客户/订单/收款/审核事实。完整业务MOCK应保持不变。
- 实际成功保存/登记/审核后标干净，再自动跳转或刷新；失败保持dirty与完整输入。不要以开始loading、固定时间或成功Toast代替已提交状态。
- 处理中的票据先按现有提交契约完成或拒绝；导航可以短提示等待而不再开“未提交”确认，不让已执行业务被误称未提交。具体处理策略由root统一，不破第4轮同对象/同会话/原表单再查。
- 同页财务历史分页优先只换历史区、保留业务form节点和校验状态；若确需销毁当前表单，纳入统一守卫。导航展开/密度/单证专注预览等非破坏性动作继续直接可用。
- 权限链接依据真实ROUTES而非硬编码臆测。无权源报价/客户/询盘显示已有可见文字，保留对象编号，避免点击后才给无权限页。商品详情对无列表权岗位返回合法订单或已知来源；没有可验证来源时返回订单列表，不依赖未知`history.back`。
- boss已允许询盘/报价/财务页面，补主导航可达性但保持只读；不得给编辑、登记或客户权限。查询入口参数只能带已存在合法订单；失效上下文保持明确错误/空态，不默默选另一对象。

## UI任务层级与披露

主任务是完成当前输入/审核并提交；次任务是辨认对象、带合法订单号/币种/版本抵达下一步或返回；参考是待办、搜索和来源规则。当前对象与短未提交状态常显；准确异常/退回意见常显；完整刷新/历史限制放使用说明或低频规则，不往用户确认框塞API术语。

离开确认使用具体对象和“继续编辑／放弃输入并离开”的含义，单证显示真实编号与版本，不加入多重批准或自动保存承诺。1280/1440检查新增导航及上下文短句不会把保存、登记、审核推到正常首屏之外；长错误继续完整显示并自然滚动。确认取消时焦点回当前或最近作业字段，无可用字段才回原触发；保留可理解的返回位置。报价未提交短状态归标题组，不挤占保存等主动作。
