日期：2026-10-07。基线：`main f13673d`。执行：单证实现 agent；`views-fin.js` 的重新制单审批由财务实现 agent 最小配合，中枢负责最终代码审查、真实浏览器、交接及提交推送。本文件记录本子任务，GitHub 回执以本轮中枢材料为准。

## 1. 已复现的问题与目标

基线中 `renderCI` / `renderPL` 每次预览都重新读取 `MOCK.seller`、客户、商品及订单。订单改价或主数据更新后，即使原单证版本“已通过”，纸张也会悄悄改变。使用 `git show f13673d:trade-doc-demo/js/...` 加载基线进 Node VM，修改卖方名称，输出 `BASELINE f13673d reproduced: seller mutation changes historical CI = true`。

目标是让每个版本有独立交易快照，并区分“修改包装备注”与“按照当前交易重新制单”。当前仍为静态内存演示，无历史数据库和真实签发记录。

## 3. 数据契约与共享接口

`snapshot` 数据结构：

```javascript
{
  schemaVersion: 1,
  basis: 'demo-baseline', // 或 creation
  capturedAt: '实际捕获瞬间的 ISO UTC 时间',
  seller: { /* 卖方字段独立副本 */ },
  customer: { /* 客户字段独立副本 */ },
  order: {
    /* 订单字段独立副本，包括 currency、tradeTerm、paymentTerm */
    items: [{ productId: '...', qty: 0, price: 0, product: { /* 商品独立副本 */ } }]
  }
}
```

- `U.captureDocumentSnapshot(doc)`：给新创建的单证捕获当前交易。创建路径完成 `doc.orderId` / 版本分配后，在 `M.documents.push` 前调用。可覆盖 JSON 克隆带来的普通 `snapshot` 属性；不能重写已经锁定的版本。
- `U.documentSnapshot(doc)`：只取已有快照；JSON 复制来的普通属性会重新锁定，缺失快照则明确抛错，不回退读取 live 数据。调用不改变已有快照值。
- `U.inheritDocumentSnapshot(target, source)`：沿用 source 的交易内容、来源类型和原捕获时间，创建独立且冻结的副本。
- 初始化内部使用 `captureDocumentSnapshot(doc, 'demo-baseline')`。不改 `mock-data.js`，不写 `localStorage` / `sessionStorage`，刷新重新从源码样例建立基线。
- CI 合计仍为快照行 `Σ(qty × price)`，币种取同一个快照订单。PL 不显示交易金额。原订单财务/收款仍基于当前订单，快照不会阻断两条并行流程。

## 4. 明确假设和真实边界

- **H07：包装与备注修订沿用交易快照。** 原因：单证员的权限仅覆盖唛头、包装、备注，不能借修订入口改变客户/商品/价格。若实际业务要求交易变更修订，应新增独立的受控申请和明确审批规则，不能解冻覆盖旧版本。撤销本假设须修改创建路径和相关回归。
- **样例基线不是历史恢复。** 现有 Demo 无当时签发数据，本轮只把“本次页面加载时”的交易冻住。`createdAt` / `updatedAt` 仍保留样例日期；`snapshot.capturedAt` 是实际捕获时间，两者不可混同。界面直接说明无法还原历史签发数据。
- **重新制单使用当前交易。** 这是本轮明确的原型策略，由审批提示说明。新版包装/备注从原版复制，制单人须按退回意见核对，不能把包装复制解释为重新匹配当前数量的真实业务确认。
- **不可变限于前端正常代码路径。** `Object.freeze` 和不可写属性防止运行中误写，不是服务端权限、防篡改签名或数据库审计。页面刷新后新增版本消失；不宣称历史凭证真实可靠或生产合规。

4. 包装备注修订保存不动核心快照；五角色编辑范围与直接保存拒绝规则维持；越权和确认前换角色不能新建修订版。
5. V1 → V2 → V3 版本分配、同确认回调重复执行拒绝。

7. finance 重新制单成功和重复处理；缺客户导致捕获失败时申请状态、处理人/时间、单证数量与旧版不变。

这些为 Node VM 的行为与 HTML 输出验证，不代表真实浏览器布局、点击、打印或历史数据正确性。真实浏览器与多视角独立代码复审由中枢统一追加证据，不在本子任务伪报完成。
