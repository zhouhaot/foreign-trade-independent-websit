## H16/H17 与现实边界

H16：没有公司汇率/币种政策时，同批商品参考币种不同就拒绝自动生成；不把商品参考价视作正式成交价。沿用 H12 数量/单价两位普通十进制、最小0.01、每行精确到分、小数数量保留，技术上可算不证明物理计件交付。

生成只建“待客户确认”报价草稿，inq.quoteId 与新Q.inquiryId 一次一致，询盘状态转“已报价”；不直接建订单/单证或收款、不登记客户确认。草稿默认 FOB 上海、30%预付/70%见提单副本、有效期初值今天沿用原实现并明确待业务员修改，不冒称匹配真实需求或企业制度。日期只是真日历校验，无新增未来/过期禁令。

H17 合成询盘 date2026-10-07 是追加样例日期，非收到实盘时间；列表/详情日期旁及来源字段明确“样例加入日期”，source/message 明确演示。中枢只加一条 INQ2026006，P001×100 + P003×50 参考545USD，不改变原五条或九报价初始事实。来源标签绑定单独 demoSynthetic 属性，不能因编辑备注而消失。INQ2 已有 Q2 的 EUR 不因现商品参考 USD 被覆盖，页面明确两者可能不同。

所有写操作只在内存，刷新恢复原始样例。私有票据、引用/内容绑定、无共享明细副本是静态原型行为，不替代服务器身份、真实多用户并发事务、数据库唯一约束、主数据版本或历史签发审计。缺失/冲突不补齐猜测值，页面给核对说明。

## 本步复盘

生成链的完整性不是“按钮没出现”：动作层也须校验身份、双向来源、数据候选和已展示内容。已有编号不等于有效关系，且“跟进中”也不能覆盖已有双向报价；冲突保留原事实供核对。自动草稿只有参考初值，默认条款/币种来源要可见，后续由业务员编辑而不是自动猜成交事实。

首轮两个独立代码视角补出了源页面漏绑：引用与内容绑定仍需要明确的路由约束。票据只有在原来源地址继续核对才可提交，已拒绝的旧票据需要重新打开。下一步中枢据真实图处理长名称、参考金额列、一次确认密度和可达主动作，独立 reviewer 复验此有限修正。这里不提前给出整轮 SHIP、生产完成或 GitHub 已同步结论。
