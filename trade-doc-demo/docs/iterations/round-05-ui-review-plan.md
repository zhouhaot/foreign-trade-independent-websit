## 任务与用户模型

Primary task：完成正在处理的报价、收款或单证输入/审核并提交；临时离开时明确选择继续填写或放弃输入，再抵达有权的下一步。离开保护解决选择机会，不是自动保存、跨页面草稿恢复或后台存储。

Secondary task：识别当前报价号/订单币种/单证号与版本，使用合法来源链接或商品返回入口接续原订单。Reference：历史收款、冻结规则、导航/搜索/通知。参考操作不应销毁正在填写的主任务，也不能把查看参考误当保存。

H14规划覆盖报价qe-form、收款pay-form、单证df-包装/唛头/备注及audit-opinion；当前app差异还选择#cust-form，规划仍称客户资料后续，须由中枢统一实际范围与材料。本计划先列为“客户表单待整合确认”，不自行扩写为全部表单已保护。客户确认/订单申请/审批弹窗的通用草稿、跨页面恢复等不得从选择器推断已完成。

H15把应用内导航与浏览器已移动历史分开。应用内先决定再写地址；本会话已知历史有索引依据，取消后原条目/目标可再次到达。未知历史只报告实际输入/地址兜底，不能说原栈完整恢复。原生刷新/关闭提示由浏览器决定，确认刷新仍复位Mock。

## State model / 状态与决策

| 状态 | 进入依据 | Must-see-now | 动作与离开条件 |
|---|---|---|---|
| 未改动 | 当前实际字段与基线一致，恢复原值亦成立 | 当前对象；短“当前输入未改动” | 合法导航直接走，不弹放弃确认 |
| 有未提交输入 | 受保护字段值/关联实际变化 | 对象；“有未提交输入 · 离开前将提示”；原错误/值仍在 | 当前提交继续可用；销毁输入的跳转先确认 |
| 正在提交 | 现有业务票据loading | 当前提交状态与短等待理由 | 按中枢约定等待/拒绝导航，不称已经成功或另叠离开确认 |
| 离开确认 | dirty且请求将销毁源DOM | 具体报价/订单/单证号Vn；只丢未提交输入、已提交记录保持 | “继续填写”/Esc留源DOM；“放弃输入并离开”才抵达目标，不写业务事实 |
| 放弃本页编辑 | doc-cancel-edit仍停当前版本，只回只读 | 具体单证对象、回只读含义 | “继续填写”/“放弃修改”；不误写“并离开” |
| 校验/延迟提交失败 | 原数字/对象/身份/内容契约拒绝 | 字段cause、原输入、dirty仍在 | 可改正再提交，失败不清基线 |
| 实际提交成功 | 完整业务记录实际写入后 | 实际结果与对象 | 先markDraftClean再导航/重建，不以Toast或loading启动清dirty |
| 同页参考变化 | 财务历史翻页/导航收展/单证专注预览 | 原表单/错误、参考当前页码 | 保源表单，直接使用；不虚构放弃或提交 |
| 无权上下文 | 当前ROUTES不允许客户/报价/询盘入口 | 原名称/编号文字 | 无假可点击样式；合法订单/商品返回仍可达 |
| 来源无法核对 | order参数缺失/重复/不含商品/无法解析 | 明确无法核对；真实商品身份 | 返回有权列表，不猜最近页面或history.back |

## Information architecture / 信息层级

| 信息 | Role / 分类 | 频率 | 首屏必要 | 容器与披露 |
|---|---|---|---|---|
| 当前对象/岗位 | Primary context | 高频 | 是 | 既有页头/表单身份，不重复新卡片 |
| 短输入状态 | Supporting status | dirty转变时 | 是，但不挤主动作 | 标题左组或既有page-description，role=status；同状态输入不反复播报 |
| 主任务字段/错误/提交 | Primary task | 高频 | 正常主动作保留 | 原表单及就近完整cause；长错误自然滚动 |
| 离开决定 | Decision | 有dirty且破坏性导航时 | 模态中全部可见 | 一次具名对话框；两个清楚动作，无二次批准 |
| 合法来源与返回 | Secondary navigation | 上下文转换时 | 是 | 商品标题下来源订单+明确返回该订单商品明细 |
| 收款历史/分页 | Reference | 按需 | 后置 | 仅换历史区；原登记form/错误/焦点不重建 |
| boss已允许查询 | Secondary navigation | 按岗位使用 | 主导航可到达 | 询盘查询/报价查询/收款与应收，仅已有权限，不扩编辑/登记 |
| 原生刷新/未知历史限制 | Explanation | 低频 | 不塞主操作区 | 使用说明/评审材料；产品提示只讲输入影响，无epoch/index/API术语 |

## Disclosure / 内容审计与延后理由

- 有未提交状态不能写“已自动保存”“草稿已保留”；放弃文案不能暗示已提交交易也会删除。当前只内存输入，跨页离开后没有恢复承诺。
- 正常状态短句足够；完整机制说明隐藏_now因为不影响当次填写，reveal通过README/使用说明。错误原因、版本/币种及来源失效属于当次决策依据，常显，不延后。
- 离开确认只在会销毁dirty输入的请求触发；筛选/导航收展/查历史/规则披露应直接可用。提交成功先清基线，不加门禁抵消已经授权的保存/审批。
- 商品只有明确order参数且唯一订单确实含当前商品时称“来源订单”；点击成交历史另一单是新上下文，不冒充原来源。无法核对时给有权列表，参数不是权限令牌。
- 无权链接改为真实文字，不能把紫色下划线/按钮样式留给不可点内容；保留客户、来源报价、询盘事实和金额，不以去链接删除业务资料。

## 首轮静态发现与小范围方案

1. `installDraftStatus`无page-description时把status作为page-head第三个flex子项，当前报价头部已有h2+actions；建议并入标题左组/同一行次文字，保持返回动作最右，1280不新起说明卡或把保存推下首屏。
2. 单证“放弃修改”覆盖统一标题，当前只写“放弃单证修改？”；建议带真实类型/no/Vn，明确回只读，保留“放弃修改”而非不准确“并离开”。
3. #cust-form与H14范围材料不一致，先交中枢统一；不能偷偷把一个附加selector称作全站草稿管理。客户确认等弹窗仍须单独报告覆盖界限。
4. 中枢代码取消确认优先恢复draftFocus最近编辑字段，规划文字为原触发控件。建议继续填写回仍存在的最近输入，无输入才回原触发；或保留触发策略，关键是实现/材料一致。用真实节点、focus与scroll记录验证，不把重建同值表单当保留。
5. boss新增入口后主导航共8个叶子，1000高窗口需确认统计/审核等末尾入口和页脚仍可到达；允许导航内部滚动，不能通过缩字/截入口满足截图。

## 可访问性实施规格

平台为桌面Web静态Demo，沿用原生按钮/链接/表单、单一role=dialog、应用inert、焦点限定。以下语义示例是规格，不是本代理对运行代码的修改；id应按当前对象唯一生成。

```html
<div class="page-head">
  <div class="page-heading">
    <h2>编辑报价 · Q2026004</h2>
    <span id="draft-status" role="status">有未提交输入 · 离开前将提示</span>
  </div>
  <div class="actions"><a href="#/quotes/Q2026004">返回详情</a></div>
</div>
<div role="dialog" aria-modal="true" aria-labelledby="leave-title"
     aria-describedby="leave-cause">
  <h3 id="leave-title">离开报价 Q2026004？</h3>
  <p id="leave-cause">放弃会丢失本页未提交输入；已提交业务记录保持原样。</p>
  <button type="button">继续填写</button>
  <button type="button">放弃输入并离开</button>
</div>
```

预期可访问树：主导航含当前页 → 当前对象标题 → 简短输入状态 → 具名字段/原错误 → 本岗位提交 → 合法来源/参考。离开时单一对话框名称含对象，原因说明输入影响，两按钮可Tab，默认焦点不落破坏性放弃；取消/Esc后返回仍存在的源字段或已约定触发点，源表单未重建。隐藏/无权入口不进Tab；纯状态不伪装按钮。最近输入return策略和程序关联只能从代码定义预期，真实读屏仍未测。

映射：1.3.1对象/状态/关系；1.4.1状态文字与橙色双表达；2.1.1原生键盘导航；2.4.3合理焦点顺序；2.4.7/2.4.11焦点可见且不被固定栏完全遮住；2.5.8至少24×24或满足间距例外（现有38px按钮保留）；3.2.2字段变化不自动导航；3.3.1具体错误保留；4.1.2具名dialog/控件；4.1.3仅dirty状态转换简短播报。没有从语义规格推导整体WCAG2.2AA、320px重排或真实读屏符合性。
