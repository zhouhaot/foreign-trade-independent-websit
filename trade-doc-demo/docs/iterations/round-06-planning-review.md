# 第6轮现实规划：询盘报价入口与客户资料提交

日期2026-10-07，开工基线`d396990f01f044a313bdb60575ef205b4756f8c5`。第5轮实现与回执已推送并由中枢独立回读；本轮进行中。本文件记录开工事实、明确假设与验收目标，不预写实现/浏览器通过。

## 为什么选这一片

优先业务员询盘→报价与客户资料：它们位于订单/新单证快照上游，写错来源或客户会传播到后续业务。第5轮保护未提交输入，但客户提交和询盘生成仍未形成与报价/收款一致的候选、身份、对象和一次性契约。先修真实动作，同时打磨同岗位的客户与询盘作业区，可形成可验证小交付。

备选包装字段也有问题：`js/views-docs.js:353`～`368`用`Number(cartons)||原文本`，可保存Infinity、负值、小数或非数字；重量/体积目前为`1,680 KGS`、`8.6 CBM`等既有文本。不能未经单位/草稿空值/送审完整度契约直接改成两位number或把交易数量改成整数。因此本轮包装只登记后续，不改近期H-12。

## H-16 / H-17与业务边界

H-16：从询盘生成参考报价时，全部意向商品须存在、参考币种相同且启用，数量/参考单价及逐行合计符合H-12。新报价按共同参考币种生成；混币种、缺商品/客户、非法数量/价格或分精度不支持时给具体原因并拒绝，不默认USD转换、不新增汇率/调整行。真正多币种参考定价规则确认后再调整此原型假设。

H-17：root只追加一条明确合成未报价询盘，供真实UI合法路径；不改原5条状态/quoteId，不预造关联报价、订单、收款、单证或客户确认。建议具体内容：

| 字段 | 保守合成值 | 解释 |
|---|---|---|
| id | INQ2026006 | 当前唯一新样例，不假称真实询盘流水 |
| customerId / salesperson | C002 / 陈明 | 复用既有客户与sales演示人，都是样例身份 |
| date | 2026-10-07 | 本次添加样例日期，不是实际收到客户需求的历史事实 |
| source / status / quoteId | 合成演示样例 / 跟进中 / null | 来源与页面留言明确演示用途，无预先报价 |
| items | P001数量100；P003数量50 | 既有保温杯/露营灯，各为个，正常整数；不改变H-12对小数数量的支持 |
| message | 【合成演示，非真实客户需求】用于体验询盘生成报价：示意100个保温杯与50个露营灯；未发生客户确认、订单或单证。 | 不能伪造真实需求、承诺交期、贸易条款或成交 |

既有参考价3.20/4.50均USD，候选为545.00USD；只作为参考报价计算检查，不是市场价格或客户同意金额。可加`demoOnly:true`元数据，但source/message可见标识必须保留；不要求新增UI测试按钮。刷新继续恢复原型样例。

原型现有生成报价的贸易/付款默认条款应可编辑并明确待核对，不能说合成客户已经接受。H-12数量0.01支持与每行精确到分、H-14/H-15离开保护、确认后才生成订单、分币种和旧单证冻结继续有效。缺失计件分割/单位精度、真实联系人有效性不自行定案。

## 最小提交契约

询盘动作仅sales，未关联报价且没有反向关联报价的真实未报价来源才可生成。原INQ5虽跟进中仍有Q5，按事实继续查看已有报价，不由状态文字推断可再创建。双向不一致、缺引用或重复关联明确提示核对，不能覆盖现存关联自愈。

开窗显示真实客户、询盘号、意向商品/数量/参考价/币种/合计与待编辑条款；绑定同账号会话引用、询盘对象身份、展示内容、客户/商品/启用字典。提交时再次检查合法性与内容；有效A变有效B也要求重开。票据一次生效、同询盘共享锁、无碰撞新ID，先构造完整报价再一次写报价与来源关联。失败无部分状态/日志；成功经统一导航进入真实新报价编辑，仍待客户确认。

客户表单绑定可见客户ID与进入时token/同sales会话/对象身份/原内容，不从当前hash猜目标；路由、表单节点或源对象变化拒绝。候选含全部可编辑字段，先全部验证后一次提交。必填非空、邮箱基本格式、等级限现有A/B/C；格式验证不等于邮箱真实可达，不网络发邮件或DNS查询。电话不凭空限制某国格式，姓名/国家不编造正规业务清单。若实现需要文本长度上限，应在helper和材料显式列为原型范围，错误拒绝而非静默截断。

失败保留字段、错误、dirty与当前/最近作业焦点，成功实际写入后才markDraftClean并反馈。改客户资料不改既有单证快照/旧纸张、订单金额或既有报价内容；下一次新快照/新报价只按其明确路径读取当前信息。当前仍假登录、内存写入，不能当作服务端授权、防篡改或主数据审计。

## UI主次任务与多轮评测

询盘主任务是读客户留言与意向商品、核对参考交易并形成可编辑报价；次任务是查看已有报价或合法商品/客户来源并返回；参考为来源渠道与时间。客户主任务是维护正确联系资料；次任务为合法关联订单与返回；旧订单/收款事实放后置参考。短对象ID、角色只读/未提交/已关联与币种常显，完整原因就近展示，不在产品塞实现术语或增加多重确认。

第一轮从业务员效率、主管只读、来源/金额真实性、键盘错误和布局五视角找问题；修复后第二轮真实1280/1440图与路径复测。核对长客户名、留言、参考说明、邮箱错误与正常保存/发起动作位置。错误内容全文保留并可纵滚，正常主动作可见，不用缩小字号或裁纸张。已有全局离开确认、成功清理和焦点策略继续验证。
