# 2026-10-14 销售链路评审修正

范围为静态 Demo 的销售页面与订单上下文。无后端、外部依赖、持久化或源业务样例改写。主代理统一更新 HANDOFF、共享工具和全局路由，本文不代替整轮交接。

## 已实现的前后行为

| 项目 | 修改前 | 修改后 |
|---|---|---|
| 改价前置试算 | 只验证目标金额格式，可能到主管端才发现尾差 | 输入时调用同一 `U.prepareRepricing`，显示数量与候选单价；有尾差、低于已收或其他不支持条件时字段就近报错并禁用提交。点击提交及异步回调再次校验 |
| 可行目标建议 | 无 | 若本次舍入候选合计再次试算可精确命中，显示“试用可行金额”按钮。必须由用户明确点击，说明需与客户协商；不静默改金额、不自动提交，也不求解任意逐行价格组合 |
| 有效期 | 草稿默认创建当天；保存不检查先后 | 默认创建日后15天；保存、客户确认与生成订单共用候选检查 `validUntil >= date`。保留过去/未来真实日期能力，不擅加企业过期制度 |
| 生成订单交期 | 空 `deliveryDate` | 新日期输入必填，默认今天后30天。原控件、输入原文、身份、报价对象/内容/状态、来源地址、模块权限在提交及异步回调核验；成功才一次生成并清本窗草稿 |
| 日期草稿保护 | 生成订单原为无输入确认 | 新 `qg-form` 沿用既有共享 Modal 草稿继续/放弃保护；处理时锁定，失败保输入，新窗不被旧回调关闭 |
| 订单入口 | “新建报价”跳报价总表 | “从询盘新建报价”指向跟进中询盘；查询参数仅作为无已有状态筛选时的默认，重置显式为空，不反复强制覆盖用户筛选 |
| 业务员协同操作 | 仅查看完整订单 | 待执行/执行中订单补“申请变更”，仍执行原审批流程 |
| 空交期 | “交期 ”悬空 | 选择卡、检视器与订单概况统一“待排期” |
| 订单概况 | 重复头部客户/金额/条款/状态 | 聚焦交期、备注、真实“未提供合同附件（当前原型未接入附件管理）”及最近3条动态；同分钟新追加记录优先。来源报价移至所有业务角色可读的头部，不丢溯源 |
| 单证入口 | 未制单订单跳总台账 | 缺任一CI/PL时用 `doc-create[data-order]` 交给单证模块补首制；全部已有时指向实际关联单证 |
| 截断提示 | 客户英文缩略无提示 | 订单表客户英文 `.cell-secondary` 增加转义后的完整 `title` |
| 页签接口 | 只有整页视图 | 新导出 `Views.orderTabBody(ctx, tab)`，保留 `#order-tab-body` 与原六页签按钮；局部更新与滚动保持由主代理接入 `app.js` |

## 文件与实现边界

- `js/views-sales.js`：上述视图、动作与输入委托；跨文件新增仅使用既有 `window.Views` / `window.Actions`。
- `scripts/verify-review-sales.cjs`：可复跑的真实 Actions / Views 最小 DOM 专项，不是浏览器布局或读屏认证。
- 依赖主代理共享 `U.addDays`、`U.prepareRepricing` 与 `U.moduleEnabled`；本子任务未修改 `utils.js`、`app.js`、CSS、Mock 或 HANDOFF。
- 新生成订单 Modal 沿用已存在的局部 Modal 按钮事件模式（与客户确认相同），应由主代理在 HANDOFF 记录该有限例外；新实时试算走 document 的 input 委托，建议按钮走全局 `data-action`。

## 限制与复盘

前置试算保证的是“本次提交时当前订单与收款条件下，目标可按现有两位单价等比规则精确命中”。订单、收款或权限以后仍可能改变，因此不承诺主管将来100%获批；审批端保留独立重查。静态前端检查不代表服务器事务、正式审批制度、真实身份或生产鉴权。

主代理负责1440×900/1366×768真实页面、改价弹窗长错误与交期Modal可用性、页签不跳动、首制CI/PL接续等最终验收。本子任务没有据 Node 结果宣称这些浏览器项目通过，也没有推送远端。
