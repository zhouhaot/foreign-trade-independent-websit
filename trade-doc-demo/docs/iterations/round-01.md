## 两轮测评与打磨

第一次：对实现代码与概念稿分别评测业务主管、业务员、单证员、财务及键盘用户的需求。采纳控件描边、选择播报、退回版本入口、成功悬停对比修正。独立代码审查核对选择/分页/空态、金额币种、HTML转义、角色与路由一致性，未发现本轮新增阻断。

第二次：真实订单1440/1280、工作台、单证、财务、登录截图复审。采纳左列本页/内部滚动提示；重拍非零滚动造成的sticky截图偏移及临时Toast遮挡，先回读`scrollY=0`再保存证据，不把拍摄偏移当作CSS缺陷。详细评语见 `.impeccable/review/round-01-a/design-review.md`。

## 实际验证与边界

- `node --check`：全部运行JS与验收脚本；四个原脚本加新增`verify-order-workspace.cjs`。原脚本覆盖12资源、9报价、7订单、11单证、金额币种、100角色视图、登录/退出、报价生成与受控修订回调。
- 新VM回归：四业务角色独立进度/币种/CTA、每页6条、换页可见选择、空结果清除CTA、非法/不在本页/管理员选择拒绝、展示切换与筛选节点保留、Mock数据未变。
- 真实HTTP浏览器：五角色×20路由＝100检查；每路由1280/1440＝200宽度检查；封版实现重跑，无页面级横向溢出或采集的console异常。
- 8组关键交互：选择/表格/密度/导航保留输入；空结果；分页；Space选择；搜索Esc/焦点；单证编辑/专注/导航保留唛头；单证员退回入口；财务所选订单入口。报告见`browser-verification.json`。
- 八张最终代表图：订单1440/1280及两种宽度的底部操作（viewport截图），单证1280、财务1280、登录1280、工作台1440（全页截图），位于同一证据目录。最终1280/1440检查额外断言实际`innerWidth`等于目标，避免把其它标签的viewport覆盖误认作本页尺寸。
- 设计结构审计：8 PASS / 1 WARN / 0 FAIL；WARN是有意保留的系统中文字体、白色表面、业务保存文案等启发式提示；不视为整体无障碍认证。主紫/白字约6.30:1、控件边框/白底约3.69:1、成功hover/白字约5.03:1，均为静态目标色值计算。
- 当前受控浏览器只允许HTTP/HTTPS，`file://`被URL安全策略拒绝，本轮未执行真实离线浏览器验收，也未绕过限制。入口仍无module/fetch/外链，结构兼容检查通过；历史file验收不能写成这轮重跑。
- 本轮未执行全部状态排列、跨浏览器、真实读屏、400%缩放、生产鉴权、后端服务或NAS部署。原Ego脚本作了模式兼容更新，但本环境实际浏览器结果来自Codex浏览器，未执行Ego脚本。

## 假设与既有风险

本轮没有扩展数据可见范围、单证种类、角色审批权限或取消期间收款规则。用于现实路线的明确假设见 IMPLEMENTATION_ROADMAP H-01～H-08。历史单证动态引用与改价舍入20.50USD差额仍未修；视觉/初始金额检查通过不覆盖这些状态变化。

## 复盘与下一轮
