## 主任务、状态与范围

主任务仍为本岗位核对当前 CI/PL 并完成下一步；纸张底部审核行属于当前版本状态反馈，不能抢占右栏主业务动作。版本、当前导出资格与冻结来源是决策上下文，历史决定与时间为参考。既有 banner、退回意见与操作留痕已经承载历史，不为一行审核表达新堆历史卡。

当前源码 renderCI/renderPL 无条件把 `d.approver || 待审核` 放在 Approved by 后，导致制作中像已送审、退回/重送待审带上次处理人似已通过。H19采用状态驱动的局部共用显示函数，不清旧 approver/approvedAt/opinion/history/snapshot、不写数据或动作、不改权限或导出资格。单证与收款/订单状态仍独立，H18包装和H12交易契约不扩展。

| 当前查看版本状态 | 纸张就近表达 | 必须保留/不得推断 |
|---|---|---|
| 草稿 / 制作中 | 未送审 / Not submitted，不填本次批准人 | 状态原名称保持；不暗示等待主管，不清历史 |
| 待审核，首次或退回后重送 | 等待本次审核 / Pending review，不以旧处理人填 Approved by | 上次退回人/日期/意见在既有留痕，当前仍待审核 |
| 已退回 | 已退回，未通过 / Returned, not approved | 原意见/处理人仍可读，不伪造批准记录 |
| 已通过且姓名/日期完整 | 仅本版本原审核姓名与既有章 | 通过是 Demo 审核记录，不等正式签字/签发 |
| 已通过但无姓名 | 审核记录待核对，不凭空补人 | 保已通过事实与原章/资格，不改待审核，不借另版本姓名 |
| 已通过有姓名但日期缺失 | 保真实原姓名，同时提示日期待核对 | 不因日期缺失删名或伪造日期；缺失异常不造正式 Mock |
| 旧已通过 / 订单取消申请中或已取消但该版曾通过 | 原通过姓名/章仍保留 | 历史只读/暂停当前导出由原操作区说明，不通过抹记录表示无资格 |
| 未知或不可识别状态 | 状态待核对，不猜批准人/待审核 | 不自动修状态，不用真值存在姓名判断通过 |

中文状态应与英文一起清楚可读，文字直接表达未通过/待审，不依红章或颜色作唯一判断。状态值只来自当前查看版本，不能借列表聚合状态/另一CI或PL/实时订单来填审核人。姓名必须转义，空白/缺失日期的显示以明确规则为准，不从送审日期或日志附近时间猜通过日期。

## 信息层级与小范围视觉方案

1. 仍保纸张 footer 左制单、右审核及原空签字线位置。当前未通过状态用普通文字替换不准确的 Approved by 姓名，已通过原审核片段尽量保持。不存在真实宽度/折行问题时不因数量制造 CSS 修改。
2. 状态句和记录缺失提示就近紧凑，使用已有正文/辅助字层级，长中文姓名/中英文状态允许折行，避免 nowrap 横滑或强截断。不得缩小交易字体、隐藏意见、挤走右栏主操作。
3. 原“授权签字 Authorized Signature”空线是模板区域，不补签名图、签署完成勾、已签/未签法律结论或额外确认。必要 Demo 范围说明优先利用既有来源/演示说明，不让纸张充满免责卡。
4. 当前状态行无需按钮、Tab 焦点或 aria-live 整纸；页头/目录/banner/纸张表达同一状态，用原有成功/失败反馈播报，不让单证重绘反复宣读全交易。
5. 历史通过章保原版事实，当前资格在操作区明确历史只读/取消暂停。既有 banner/history够用，不重复追加“上次决定”卡；确需短句时须明确过去式并来自可验证记录。

## 语义规格与预期可访问树

以下是显示规格示例，非本代理写入运行页。静态纸张审核字段可直接用具名可读文本，不引入多余 live region；状态与姓名必须各自有完整含义。

```html
<div class="paper-review">
  <div>审核状态 Review status：等待本次审核 / Pending review</div>
  <div class="s-line">授权签字 Authorized Signature</div>
</div>
```

预期树：单证类型/no/Vn/真实状态 → 当前版本或历史版本上下文 → 纸张交易字段 → 包装/备注 → 制单人 → 当前审核状态（或已通过审核姓名/记录待核对提示）→ 模板签字栏 → 现有历史/操作区。这是可访问内容目标，不是已执行读屏播报；空签字线仅视觉模板，不能以 aria-label 冒称真实签名。

SC 1.3.1/4.1.2：字段名称与状态含义清楚，若使用 heading/段落不改变正确层级；1.4.1：是否通过由文字与状态决定，章色不作唯一信息；1.4.3/1.4.11：沿现A文本与边界，新增局部色须实算；2.4.3/2.4.7/2.4.11：无新增装饰Tab项，已有业务操作焦点顺序/可见性不退化；4.1.3：复用实际状态反馈，不将全纸设 assertive。此轮没有新可点击组件，不以一行静态状态声称满足全部WCAG2.2AA、400%或读屏。

## 五组视角与验收重点

| 视角 | 第一轮问题 | 修正后验收 |
|---|---|---|
| 制单员 | 制作中/草稿是否仍像已送审；退回/重送是否误读本次通过 | 原生PL退回→重送后纸张等待本次审核，当前输入/包装规则、保存与送审主动作原样 |
| 主管 | 看纸张能否判断等待本次处理，上次决定与当前审批是否混淆 | 通过前无批准人语义，通过后仅本次/本版本姓名；取消确认保意见/原交互，不新增审核门禁 |
| 只读业务员/财务 | 纸张与页头/目录同事实，章是否被误当当前可导出 | 原查看权限、返回订单保持；历史通过/取消暂停仍可区分，收款与订单金额未变 |
| 视觉/认知与键盘 | 长中英文/名字是否折行，模板线是否暗示签署，颜色单义，焦点是否受新布局遮挡 | 实际两宽footer双列可读/无横滑，主动作/既有焦点不退化；静态状态不用额外Tab/live卡 |
| 现实与历史 | 是否清旧人/时间/意见来修视觉；缺记录是否造批准人/日期；旧章是否被取消擦除 | 共用renderer只读、Views前后全MOCK一致；动作仅原变化；旧交易/快照/决定保持，模板签字无正式承诺 |
