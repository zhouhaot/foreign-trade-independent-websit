## 改进与前后行为

| 改进 | 原行为及影响 | 当前行为及验证 |
|---|---|---|
| 普通十进制与预览 | `Number(value) || 0` 接受指数/十六进制/Infinity，空值变零；没有精度或安全范围约束 | 使用 `U.decimalInput`/`U.transactionAmounts`，至少 0.01、最多两位小数；非法行与合计标“待修正”，不伪造零金额。输入真实监听夹具先得到 RED：Infinity 显示 `∞`，实现后拒绝并全 MOCK 不变 |
| 行金额到分 | 数量与单价乘积任意舍入到两位显示，0.01×0.01 等不足分金额可写入 | BigInt 中间乘积由共享工具处理；每行必须精确到分，行与合计不越安全范围；不足分给具体行号及原因，不静默四舍五入。小数数量继续允许，0.01×1.00 与 10.25×4.00 合计 41.01 正常保存 |
| 可读字段错误 | 明细没有独立错误容器、匿名输入，失败只 Toast 笼统说明 | 数量/单价具名到行、`inputmode=decimal`、规则提示和字段错误，`aria-invalid` 与错误关联由现有工具生成；总体处理说明 `role=alert`，定位首个相关字段，未知关联资料定位保存按钮 |
| 日期、币种与关联 | 日期只判非空，币种硬编码 USD/EUR，客户/商品缺失会直接解引用 | 真日历日期校验支持合法闰日；币种读取当前启用字典，CNY 停用/未知币种拒绝；客户/商品必须唯一有效关联，缺失/重复给核对信息，坏明细可打开编辑页且无法保存。贸易及付款条款仍为必填自由文本，不猜造企业业务制度 |
| 保存绑定与原子写 | 保存按当时 hash 选报价，先改条款再逐行改数量，缺身份/对象/状态重查 | 渲染时创建私有上下文，表单绑定报价 ID/上下文 token；提交先生成独立候选，全项通过后在真实 Promise 回调复查页面、操作者引用/内容、报价对象/状态/全部内容、客户/商品/币种字典。失败无业务部分写入，点击后修改表单不改变已校验候选 |
| 客户确认 | 没有动作层角色/状态约束，回调再次读取仍可编辑的日期/说明；失败也安排成功定时反馈 | 仅 sales、待客户确认且无订单的报价办理；开窗展示客户、金额/币种、贸易/付款条款、日期与每行数量/单价/金额。确认日期与说明在点击时捕获；状态/对象/主数据变化拒绝且保留处理说明，只在实际成功后反馈 |
| 来源一致且一次生成 | 生成订单缺 sales 权限和报价内容绑定，延迟有效 A→有效 B 漂移可被接受 | 仅 sales、已确认且无订单，校验确认日期/交易资料；确认窗口绑定展示内容。重复按钮、被替换旧弹窗、同报价双窗口只生效一次；同时查 quote.orderId 与 orders.quoteId，防半关联状态重复。订单明细复制规范数据，不与报价共享 items 引用 |
| 取消与重复 | 部分异步入口关闭后仍可能继续写或假成功 | 确认及生成捕获本窗口引用，关闭或被新窗口替换后不写；编辑页切走/替换表单时延迟保存拒绝。私有跨动作 busy 与每次上下文 submitted 避免同提交重复。未增加全局草稿离开保护，普通保存前取消仍丢弃尚未提交的输入 |

## 假设与边界

- 与规划 H12 同范围：报价数量/单价采用两位普通十进制；每行金额精确到分，不提供企业舍入制度。它保留原 `min=0.01` 的小数数量能力，没有改为整数。
- 无正式政策证据，不要求报价有效期/客户确认日期必须未来，也不禁止早于当前日期。只校验有效日历值；2024-02-29 专门作为合法历史日期回归，2026-02-30 与 2025-02-29 拒绝。
- 币种从当前字典的启用项选择；不按商品参考币种限制成交币种，现有 EUR 报价继续有效，没有自动汇率/换算。客户/商品唯一关联和开窗内容绑定只是内存原型核对，不是主数据版本制度或真实鉴权。
- 金额候选中的 `lineCents` 仅计算/展示，保存报价和生成订单仍只持久于内存 `productId/qty/price` 原字段；刷新还原 Mock，单证/收款/历史快照不改。
- 自动编号是现有 Demo 的订单编号序列，补安全整数/格式/冲突拒绝；不宣称数据库唯一约束或多设备并发安全。
- 当前 Promise 检查是前端延迟模拟，不替代服务端鉴权/事务。引用及内容漂移是合成共享内存夹具，不声称已证实真实多用户并发问题。
