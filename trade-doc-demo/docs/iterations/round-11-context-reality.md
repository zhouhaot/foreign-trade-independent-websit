## 现实风险与可验方案

1. **历史结果误当当前状态**：台账“已退回/已通过”是该次申请结果；关联页展示当前对象。用原SO2“已退回取消/执行中”路径检查不会形成“订单已取消”的误读；SO1旧改价通过不赋予再次批准入口。
2. **从标题猜目标**：关联只能来自 `targetType/targetId` 与唯一真实对象。原PL重制理由说V2，链接仍V1；旧AP60801未记录targetAmount，保持未记录。不能用标题代替主键或填缺失事实。
3. **版本与资格偷换**：按申请精确文书id编码链接；不是自动最新。doc原CI3V2合法修订/导出演示应仍由policy给出，PL4V1已有重制申请禁止重复申请。查看入口不增加审核权或改actor/单证状态。
4. **扩大本人范围**：比较本表每岗位集合、顺序/次数、空态，核台账新理由/意见都来自原记录；财务保持0/0，管理员由原route拒绝，主管不自审。
5. **缺目标、重复目标、未知类型**：这些原样Mock没有异常。只能在独立Node VM中模拟并期望“待核对/不可定位”、无死链、无标题猜测，随后证明视图不额外写入；不修改Mock源码造真实截图、不冒作原客户事实。本复核没有预写此异常矩阵已通过，实施专用脚本需实际证明。
6. **长理由/意见与安全表达**：完整可读、原文转义，查看入口使用固定站内前缀与编码；不截去原因只剩颜色或一行标题。HTML/特殊id案例只隔离Node；真实两宽与键盘可达由中枢实测，不以字符串断言代替视觉。
