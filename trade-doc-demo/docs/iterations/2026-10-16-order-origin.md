# 逐订单起运地修正

## 用户决定与本轮范围

需求方指出上一版订单光迹的起点不合理，选择“按每笔订单的实际起运城市／港口”。现有7单无独立起运数据；随后需求方授权“待补，或者你可以自行生成样例数据”。本轮按该授权给7单编制可识别的合成起运记录，不把假数据称为真实出运。不使用公司地址统一起点，不从FOB/CIF/EXW/CFR文字解析起点。

前版的“国家旁固定偏移光迹”已移除。现在方点是订单记录的起运城市/港口、圆点仍是客户国家近似锚点，箭头及一次可重播光迹按该方向绘制。**这不是实际运输路线、实际到港位置或实时物流，不意味着订单已出运。** 全部原状态继续保留，取消申请中的历史业务也可查阅。

## 地点锚点与几何

近似坐标参考[UNECE UN/LOCODE 中国地点索引](https://service.unece.org/trade/locode/cn.htm)的官方搜索索引结果：Shanghai Pt（CN SHG）3038N 12204E；Ningbo（CN NBO）2952N 12133E；Yantian（CN YTN）2236N 11418E。经纬转十进制用于地理示意，上海港(122.066667,30.633333)、宁波市(121.55,29.866667)、盐田(114.3,22.6)；不是精确泊位或客户实际货物坐标。直接打开官方页面返回403，因此使用官方检索索引的缓存内容，不声称完成2026版港口数据认证。

`U.orderShippingOrigin`只读取明确字段，校验名称/种类、有限数值及全球经纬范围；0度合法，字符串/null/非有限/越界拒绝。缺失与无效显示待补或具体待核原因。`U.orderMapRouteSegments`只在底图可显示纬度[-60,85]内生成；极区不强制夹到错误位置。未知客户国家、缺起点、超范围和重合起讫位置保订单/金额，但不制造假线路。

二次曲线端点直接投影逐单坐标；反经线处分两段，使用De Casteljau插值保持曲线连续，避免从中国向美洲横贯欧洲。仅最终段绘箭头，两段光迹按各段参数区间顺序播放；这是图形流向，非海上/航空路径规划。同国不同起点仍是两笔线路，国家选择只淡化其他国家路线，不重建画布/按钮。原三进度、金额/付款/单证快照和写动作未改。

## 缓存缺陷与静态约束

实际验收出现旧utils与新地图脚本混载，导致`U.orderShippingOrigin is not a function`及工作台空白。对测试页禁用缓存后证实服务器当前源码正常，之后为入口12个本地资源增加明确版本参数，最终pages.css使用`20261016-origin-2`；QA入口query也更新以读取新HTML。`verify-demo.cjs`先核原URL无外部来源，再剥离query核本地路径/语法，仍严格12资源。没有框架、外部地图服务、构建工具、fetch/module或业务持久化。
