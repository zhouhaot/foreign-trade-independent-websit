# 第 3 轮：单证预览审核 UI 小范围方案

日期：2026-10-07。基线：`ef83c20`。范围：单证三栏/窄桌面横向目录、版本切换、退回意见、来源说明与角色主操作；保持 A 珍珠白/鸢尾紫/薄荷青、当前纯静态约束。本文件是实施前设计计划，尚未描述本轮实现或真实浏览器通过。

## 1. 首轮评测与任务模型

重新打开第2轮 `document-boss-1280.png`、`document-doc-1280.png` 并阅读当前 `views-docs.js`/CSS。历史图只是当前基线的参考，不算第3轮重跑。

| 发现 | 实际影响 | 本轮最小修正 |
|---|---|---|
| 1280px上方横排全局11个版本，跨订单与版本链混排 | 员工难判断正在切换同一订单文书、同一文书版本，还是另一订单 | 本订单优先，当前文书链置前，CI/PL与最新/历史身份明确；其它订单入口保留 |
| 右栏先单据信息/来源，再角色动作 | 主管最常用通过/退回在1000px视口底部；稍长来源/意见就需要额外滚动 | 角色主任务与必要意见前置，元数据/来源短句后置；长规则仍原生details |
| 当前通过banner直接称本版本可导出 | 与取消/旧版本的新资格契约冲突，历史审核事实与当前资格易混淆 | 纸张外独立显示“该版本曾审核通过”及当前导出资格/阻断原因，保留原历史章 |
| 退回意见在纸张上方及单证员右栏出现 | 信息存在，但长意见会挤压重送/重新制单动作 | 常显退回事实、具体意见与下一步；不裁切或只放hover，按长度自然滚动 |
| 版本切换是直接hash导航 | 编辑内容/未提交审核意见可能被重建页面丢弃 | 保留本地未提交输入，或提供具体离开确认；取消不丢原文/焦点，不能悄悄自动保存 |

主任务按角色分化：主管核对**当前有效待审版本**并提交意见/通过或退回；单证员完成制作/修订并送审；业务员/财务只读核对文书与实际交易/收款；已通过有效版本以导出演示为主，受控修订为辅助。版本/来源/资格是决策支持，不让全局目录与长规则占据主操作位置。

## 2. 本轮明确的业务设计边界

中枢已采纳规划 H09–H11：取消申请中/已取消禁止单证写操作与导出演示，保留历史审核状态和冻结交易；同订单同类型的最新已通过版本才有导出资格，旧版只读。此处是本轮显式原型契约，不推为真实法律/生产规则。

实时订单负责当前操作资格，版本快照负责纸张交易内容，不能用旧快照中的订单执行状态授权当前导出。已通过历史版本保持真实 `status` 与纸张审核章，**在纸张外**说明“该版本曾审核通过”，另说明“当前为历史版本，仅供查看”“订单取消申请中/已取消”或实际资格条件。不得为禁用导出改掉历史状态、删除章或更新原冻结内容。

如果同订单同类型出现不同单证编号或相同最高版本冲突，不按全局最大数字猜出继承链；保留所有记录可读，显示“版本关系需核对”和具体冲突线索，由公共资格策略决定不确定操作的阻断。UI不得自己创建新状态、修复编号或直接变更版本。

## 3. 目录与版本切换：优先本订单，保留其它订单

推荐本轮默认目录仅呈现当前订单的单证版本；标题改为“本订单单证 · SOxxxx”，计数“X个版本”。当前 `type + no` 文书链置前，其余本订单CI/PL次之；链内版本按新到旧排序。顺序仅改变可见阅读次序，不删数据。

每项始终显示：单证类型/编号、Vn、真实状态、版本身份。身份为“最新版本”“历史版本”“版本关系需核对”，不能把真实状态标签换成身份标签。当前查看项用浅紫背景/紫色竖标与可读“当前查看”，以及 `aria-current="page"`；不能只改颜色。

最新/历史身份必须来自中枢公共资格策略，不能由目录为了排序而自行取最大版本宣布“最新”；同类型编号或最高版本冲突时只标关系需核对。目录可按版本排序，但排序不授予资格。

跨订单访问采用以下二选一，优先方案1，避免本轮扩大搜索/路由能力：

1. 常显“全部单证台账”链接到现有 `#/documents`，保留原列表全部版本与筛选；页头“返回列表”可改成同一明确名称。没有丢失其它订单入口，也不声称已按当前订单过滤列表。
2. 若需保持原目录一跳访问其它订单，增加原生details“其它订单单证（Y个版本）”，展开才显示原全局其它项。关闭时控件不进Tab；保持本订单区与其它区具名，不新增手动折叠事件或外部依赖。

两种路径不同时占据主要阅读空间。1280px保留上方横向目录，1440px+保持左栏；长链横向/纵向自然滚动，至少一个当前查看项可见。最后目录项可以部分露出提示可滚动，但当前项不能永久在视口外；必须使用真实UI滚动保持定位，不为截图改选中状态。

版本切换需检测本页未提交编辑/审核意见：可以在AppUI内按文书ID暂存输入（不写业务数据/持久化），或确认“尚有未保存的唛头、包装、备注/审核意见，切换将丢弃”，选取消保留输入和焦点，选确认才导航。没有更改时直接切换。跨账号退出仍遵循原清除临时状态规则。

## 4. 右栏主操作与可见性

| 角色/状态 | 前置主区 | 辅助区/理由 |
|---|---|---|
| 主管/当前有效待审核 | 审核意见 → 审核通过（绿色）/退回修改（红色次级） | 制单人、版本、冻结来源在同屏可核对；自制自审显示具体禁止理由 |
| 单证员/当前有效草稿或制作中 | 编辑或保存草稿 → 提交审核（紫色） | 放弃修改次级，交易字段只读边界在纸张旁保留 |
| 单证员/当前有效已退回 | 退回意见常显 → 编辑修订/重新送审 | 重新制单申请为辅助，说明采用当前交易；不是自动改变原快照 |
| 当前有效已通过，允许导出 | 导出PDF（演示）为紫色主动作 | 单证员包装备注修订为次动作，完整aria-label/确认框保留新版本含义 |
| 历史版本/取消申请中/已取消/冲突 | 只读与具体不可操作原因 | 保留真实历史状态、章、快照、意见；禁用按钮旁文字说明，不能依赖禁用控件title |
| 业务员/财务 | 明确只读，按资格允许导出演示或查看 | 订单/收款事实链接为辅助，不提供制作/审核按钮 |

当前有效待审等判定以中枢资格helper为准；右栏渲染与动作入口二次校验必须一致，UI显示不是安全边界。取消流程的新行为由对应实现agent验证；本文件不对未经确认的真实退款/重开业务加规则。

推荐右栏顺序：当前任务/资格短句 → 角色操作与必要意见 → 单据信息（编号/类型/订单/制单人/更新）→ 交易来源短句与北京时间 → 原生冻结规则。退回意见是action-critical，禁止只折到历史留痕；长意见可自然展开滚动，不能截断关键原因。已通过导出后不伪造“真实文件已签发”，保留Demo提示。

## 5. 最小间距与首屏目标

保持现有字号（正文13px、辅助12px、纸张12–12.5px）、38px标准按钮和30px summary，不把视觉密度指标变成字号缩小。

- 单证页专用上padding 20–22px，标题区下间隔12–16px；当前来源说明只保留一行状态/边界，避免第二张大说明卡。
- 1280目录条每项可约160–176px，保留类型/编号/版本/状态/身份；优先保证当前订单链，不缩字号挤全局11项。
- 右栏panel-body padding12–14px，业务分组gap/底间距10–12px；主管主动作放在意见字段后，38px按钮仍完整。
- 1440宽桌面可在184px目录与232px操作栏之间保留弹性纸张，1280仍使用上目录+弹性纸张/210px操作区；不改变纸张最小阅读宽度，不新增移动端承诺。

1280×1000及1440×1000，正常短意见/当前有效版本，page scrollY=0时主动作完整可见，目标bottom≤980px；单证员已通过有效版本的导出/主管待审通过和退回都作为主业务范围。不可用/历史版本的禁用导出可作为下方低频参考；长意见、冻结规则展开和复杂冲突允许自然滚动，不为达标使用overflow:hidden裁切。

## 6. 语义示例、无障碍树与焦点流

语义示例只说明结构，未写入运行代码：

```html
<nav aria-label="本订单单证版本">
  <button type="button" data-action="doc-goto" data-id="D-CI2026003-V2" aria-current="page">
    商业发票 CI2026003 V2 · 已通过 · 最新版本 · 当前查看
  </button>
  <button type="button" data-action="doc-goto" data-id="D-CI2026003-V1">
    商业发票 CI2026003 V1 · 已退回 · 历史版本
  </button>
  <a href="#/documents">全部单证台账</a>
</nav>
<section aria-label="当前版本操作资格">
  <p>当前查看最新已通过版本。导出资格以当前订单状态和版本关系核验结果为准。</p>
</section>
```

无障碍树：单证标题/版本/真实状态 → 本订单具名目录及当前项/版本身份 → 纸张外当前资格/退回意见 → 可选择文本的文书区域 → 具名角色操作/意见输入 → 来源与时间 → 原生冻结规则 → 留痕。装饰图标/章不替代真实状态文字。

Tab顺序跟随真实DOM任务顺序。目录按钮Enter/Space导航后，新的具名标题或当前项得到合理定位，旧/新文书可辨认；未保存确认取消恢复原输入与触发焦点。原生summary支持键盘展开且不重建审核输入。禁用原因用关联文字/aria-describedby读取，禁止依赖不可聚焦按钮hover。主动作被sticky顶栏完全遮住时必须调整滚动位置，不能把遮挡截图当通过。

对应WCAG 2.2设计约束：1.3.1信息关系、1.4.1颜色非唯一识别、1.4.3文本对比、1.4.11非文本对比、2.1.1键盘、2.4.7焦点可见、2.4.11焦点未完全遮挡、2.5.8目标尺寸、3.3.1具体错误原因、4.1.2名称/角色/值、4.1.3简短状态消息。这里只是规范映射；真实读屏、400%缩放/窄重排和跨浏览器未执行时不声称整站合规。

## 7. 五视角验收

| 视角 | 具体场景 | 必须达到 |
|---|---|---|
| 主管 | 当前待审、自己制单、历史版本、取消申请/已取消 | 主通过/退回首屏，具体权限原因；历史章/状态保留但无当前可导出假承诺；无自制自审；意见不因目录误切丢失 |
| 单证员 | 草稿/制作、已退回、已通过最新、V1历史/V2最新、取消 | 退回意见常显，修订/送审次序清楚；只读交易字段不解冻；历史只读；取消禁写/禁导出但保留原事实；有效导出首屏 |
| 业务员 | CI/PL切换、本订单与其它订单台账 | 来源报价/订单可追踪；当前链/历史身份清楚；跨订单入口仍存在；不获得制作/审核权 |
| 财务 | 当前订单改价后看旧纸张、取消且已有收款 | 当前资格读live、纸张读snapshot且边界可解释；不修改已收/跨币种合并；导出只是演示 |
| 键盘/读屏 | Tab遍历、版本切换、取消离开、summary展开、冲突/禁用 | 名称/当前项/原因可读；焦点合理、输入保留；无不可見重复控件；纯状态不进Tab；未执行读屏时明确限制 |

管理员仍没有业务审批入口，作为权限回归补验，不在上述五个测评视角之外扩展业务。

## 8. 两轮打磨与证据

第一轮本文件/静态实现审查先收敛目录范围、动作次序、资格与历史事实；中枢与运行模块agent实施后，由本UIagent逐张回读真实截图并记录发现→修正→再次验证。

固定实际tab分别1280×1000/1440×1000，记录innerWidth、scrollY、opacity=1、主按钮top/bottom、来源是否展开；优先viewport截图，长文另以真实滚动补拍，不能用fullPage异常或文件名冒称尺寸。至少覆盖主管待审、单证员最新通过、退回、历史版本、取消；缺状态只在测试夹具/真实UI流程构造，不为截图修改正式MOCK。

版本和取消动作需要渲染/直接动作/延迟确认的业务测试；UI SHIP仅说明当前已验证前端范围。DESIGN与sidecar在最终反馈确认后同步；本阶段不编辑它们，不修改JS/CSS/身份/Git/HANDOFF。
