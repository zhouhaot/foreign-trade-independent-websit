# 第 8 轮：纸张审核姓名与当前版本状态

日期：2026-10-07。本轮开工基线为中枢已推送并核验的 `7d5bbae486e7509044e4e1d1158b3fa9d03ec3aa`（第 7 轮回执）。实现 agent 仅负责 `js/views-docs.js`、`scripts/verify-document-approval-display.cjs` 和本说明；中枢负责 CSS、实际 UI、多视角复审、交接与 GitHub 回执。未改 Mock、共享工具、动作状态或历史数据。

## 原问题与真实红灯

CI/PL 原纸张一律把 `d.approver` 写进 `审核 Approved by`，无姓名则写“待审核”。但 `approver` 同时保存退回处理人，重新送审也有意保留上次决定。因此，PL4 已退回或重送待审时，纸张会把上次退回人周建国标成批准人；制作中又被含混写成待审核。

专用脚本先读取未修改的真实 PL4 样例并生成纸张，退出码 **1**：“PL4 已退回不能把退回处理人显示为 Approved by”。修正后同一断言与完整矩阵转绿。旧章本来只看 `d.status === 已通过`，没有复现章逻辑错误，本轮保持它。

## H19：可撤销的展示契约

当前查看版本的 `status` 决定纸张审核状态；姓名只有在该版本已通过且有可见文字时填入 Approved by。历史决定继续保留，不用旧退回人代替本次批准人。姓名不做身份/格式/长度认证，只检查空或纯不可见内容并转义，保留正常多语言、连接字符和 emoji 原文。

| 当前版本 | 本轮纸张表达 | 保留的事实 |
| --- | --- | --- |
| 草稿/制作中 | 未送审 / Not submitted | 原记录与快照不动 |
| 首次或重送待审 | 等待本次审核 / Pending review | 上次退回人、日期、意见和 history 保留 |
| 已退回 | 已退回、未通过 / Returned, not approved | 退回说明和处理人仍在原状态横幅/留痕 |
| 已通过，姓名与日期存在 | 原 Approved by 姓名和原模板签字线 | 通过姓名片段原样，章原样 |
| 已通过，姓名存在但日期缺失 | 原姓名 + “审核日期待核对” | 不抹姓名、不补日期、不改章 |
| 已通过，无可见姓名 | 本版本已通过 · 审核记录待核对 | 不借其它版本/单据补人，不改已通过状态或章 |
| 旧已通过、取消订单的已通过版本 | 仍保该版本通过姓名/章 | 实时操作区继续只读/暂停导出 |
| 未知状态 | 状态待核对 / Status needs checking | 不默认制作中或通过，不自修状态 |

H19 是 Demo 审核表达，不是正式签署、真实授权或法律效力判断。原 Authorized Signature 线保留为模板，不推断实际已签字/未签字。以后企业明确纸张审核和正式签字的关系后，可撤销/调整展示与测试，不覆盖旧版本、交易快照或历史决定。

## 原通过片段与只读边界

完整姓名/日期的已通过记录保留原 `<div><div>审核 Approved by：…</div><div class="s-line">授权签字 Authorized Signature</div></div>` 片段。制单人、卖方、买方、商品、数量、价格、金额、币种、包装、备注与既有章逻辑未改。

没有在 Views 内清理 `approver`、`approvedAt`、`opinion`、`history` 或 snapshot。真实重送仍只按原动作追加历史与待审申请，上次决定原样；本次主管通过才由原动作写本次通过记录。新展示不能替代服务端审计或正式签署证明。

## 实际测试

`node scripts/verify-document-approval-display.cjs` 最终通过 **137 组**：CI/PL × 四业务角色 × 15 状态/异常/资格组合，外加长姓名、多语言/连接 emoji、HTML 姓名/意见、控制码边界和真实 PL4 重送→通过。每个纯 Views 组合前后全 MOCK 逐字一致；章只按当前查看版本通过状态；旧/取消版本不放宽 canExport；通过姓名片段精确保留。实际动作前后旧 history 前缀、snapshot 与收款断言保留。

综合独立审查 MEDIUM 的根因是第一版可见性检查仅排 Unicode White_Space 和 Default_Ignorable_Code_Point，未排 Control/Cc，`\u0001\u0007` 会被误当成可见姓名或日期。新增 CI/PL × 纯控制码姓名/日期四个反例后先运行退出码 **1**，首错“CI: 只有 Cc 控制码的姓名不是可见姓名”。有限修正为局部 `hasVisibleReviewText` 在判断副本排 Cc，复用到姓名和日期；四反例转绿。再加 CI/PL 中“可见姓名夹控制码”的两条边界，原可见姓名文本和全 MOCK 仍不变。此处只是存在可见内容判断，不做保存清洗、姓名合法身份校验或日期格式制度；正常多语言连接/emoji 原文继续保留。

相邻实际执行通过：生命周期 90、包装动作 111、包装候选 644、角色视图 100、draft-adapters 17、document-workspace、document-snapshots 和 demo 资源/初始金额。修改运行 JS 与新增脚本 `node --check` 通过。没有为新展示修改或删除旧测试断言。

这些是 Node VM/最小 DOM 的行为与字符串输出证据。没有在本子任务执行真实浏览器、键盘/读屏认证、打印/PDF、正式签署或生产后端。中枢的实际 HTTP 1280/1440、多视角截图、布局修正与独立终审需另记，不能用本脚本称 UI Ship。

## 复盘与交接

本轮关键是将“当前版本审核状态”“此前决定”“当前可导出资格”分开。不清数据也能修正误读，保留可信历史比把纸张统一显示一个旧姓名更准确。缺信息的情况以待核对表达，不填假人员或日期。
