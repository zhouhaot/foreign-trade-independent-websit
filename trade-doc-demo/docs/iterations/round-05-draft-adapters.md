# 第 5 轮：单证草稿与收款局部翻页适配

状态：适配实现及隔离回归通过；真实浏览器、共享路由保护的完整验证和独立复审由中枢封版记录。

## 为什么改

第 3 轮单证只保护自身目录/返回链接，其他导航另走应用路由。接入全局未提交输入保护后，继续使用局部确认会产生两份提示或提前清除编辑上下文。收款历史分页原先整页重绘，会丢失同页尚未登记的金额、备注、错误状态和提交中的表单引用。

## 每项改进

| 改进 | 原行为 → 当前行为 | 所属文件与验证 |
| --- | --- | --- |
| 单证离开入口统一 | 目录/返回链接自己比较并确认 → 真实应用交给 `App.requestNavigation(destination)`，等待获准后由共享入口清编辑状态；本层不再另开确认 | `js/views-docs.js`；真实 app click 委托测试两入口仅转交一次，未提前改 route/editing/DOM/业务值 |
| 明确放弃修改 | 「放弃修改」立即清编辑 → 通过 `App.confirmDiscard(callback, options)`；取消保留节点/输入，确认才清编辑并回只读预览，无修改直接回调 | `js/views-docs.js`；适配边界测试有变化等待 callback、无变化同步执行 |
| 成功保存后清草稿状态 | 业务成功重绘/跳转可被识别成未提交输入 → 草稿保存、送审、审核通过/退回、修订、重制申请成功后先 `App.markDraftClean()`；失败不调用 | `js/views-docs.js`；实际保存/送审/通过/退回动作及权限漂移、无审核意见失败 |
| 成功收款接续当前订单 | 实际登记后直接 hash → 业务记录/日志成功写入才 clean；跨 hash 优先共享导航，同 hash 仍重绘。输入或业务重查失败不 clean | `js/views-fin.js`；成功后 clean 与导航顺序、取消状态漂移失败保持未提交状态 |
| 收款历史局部翻页 | 全页重绘 → 仅替换 `#pay-records-content` 的历史表格与分页；登记 form 节点、字段/选单、完整错误、ARIA 错误关联、输入与焦点保留 | `js/views-fin.js`；八条记录 6/2 行分页、错误金额/备注与原节点身份/零重绘/零业务写入核对 |
| 分页焦点与滚动 | 全页重建导致焦点丢失 → 原焦点在登记区时保持；原焦点是被替换页码时落到新当前页码，使用 preventScroll，再回读原滚动坐标 | `js/views-fin.js`；隔离桩断言输入焦点不变、页码焦点恢复、scroll 259 回写；真实页面可实现的滚动范围仍由浏览器决定 |
| 提交引用不因查历史失效 | 正在登记时翻历史卸载原 form → 局部翻页保留原提交引用，不额外登记或修改金额；成功清状态，失败保留输入 | `js/views-fin.js`；真实 Promise 排队期间翻页后恰好一笔收款、原备注和金额一致 |
| 旧隔离 fixture 兼容 | 所有测试立刻依赖全局 App API → 无共享导航 API 时仍保留旧单证局部离开确认；真实应用有 API 时只走共享入口 | `js/views-docs.js`；显式删除 API 的旧桩离开/取消保护与既有生命周期回归 |

共享 API 由中枢在 `js/app.js` 实现，适配层没有修改业务金额、权限、版本、取消状态、历史快照或存储契约。没有为分页调用 `markDraftClean`，查历史不会把未登记输入当作已提交。

## 验证与限制

新 `scripts/verify-draft-adapters.cjs`：16 场景 PASS。复用实际 app click 委托、收款原生 submit 监听器、真实 `U.withLoading`、Promise 和短真实定时器，DOM 为最小隔离桩。共享 guard 在该脚本中通过 API 边界桩验证调用和时机；完整侧栏/搜索/铃铛/Back/beforeunload/提交中离开由中枢其他脚本及浏览器验证，不在这里宣称已测。

既有 `verify-payments-contract.cjs` 71 场景、`verify-document-lifecycle.cjs` 90 场景、快照与取消回归 PASS。旧 `verify-document-workspace.cjs` 初次遇到挂载未更新全局草稿基线的桩缺口，中枢已在 mount 后接入 `App.markDraftClean` 并保留单证/审核意见 trim 语义，本 agent 随后独立重跑 PASS。三份所属 JS 语法及所属差异检查 PASS；后续统一结果以中枢记录为准。

此次适配自身未执行真实浏览器、读屏、跨浏览器/旧浏览器、file://、打印、银行/服务器事务或持久化；分页恢复滚动坐标的隔离桩通过不等于所有高度变化下视觉位置不动。

## 复盘

适配的重点是业务成功才解除草稿保护、查看同页历史不会丢失登记输入。共享入口持有离开决策，模块只提供获准后的行为，避免多处确认互相覆盖。金额/权限继续由前轮提交契约负责，翻页只改变记录呈现。中枢将根据浏览器和独立测评继续打磨，不把适配测试通过当作全局导航已完全验证。
