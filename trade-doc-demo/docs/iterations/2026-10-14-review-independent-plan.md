# 2026-10-14 全量改进：独立权限审计与验收计划

本文件是实施前的独立审计及验收建议，不是完成报告。已读本目录 `AGENTS.md` 与 `HANDOFF.md`；审阅基线 HEAD 为 `f8643db82e4daf0f41904a37ab34cdc071393365`。原交接历史已在上一阶段完整读取，本次核对最新状态及追加记录。仅新增本计划，未改生产源码、旧测试或交接文档，未操作浏览器。

## 1. 用户本轮范围与约束

主代理转交的范围包括：权限矩阵真实影响菜单/路由/搜索且岗位不可夺权；财务结清后续办、标准千分位清洗与全额填入；首页会话新增笔数/待办前置/语义色；订单页签局部更新并保滚动；询盘待办过滤已有报价；只读角色弱化新建入口；改价实时预试算、报价有效期15天、交期默认30天且必填；首份CI/PL、包装单位默认、编辑焦点与错误、实际CI关联号、重制互斥、审核续审、窄屏目录折叠。角色快捷切换与原退出重登规则存在冲突，主代理正向用户询问；未获明确变更前沿用退出重登。

静态HTML/CSS/普通JS、无后端/构建/外部依赖、兼容file协议、业务写入仅内存仍有效。本轮有效权限是前端演示契约；不把它称为真实身份认证或服务端授权。

## 2. 已核实的权限现状

1. `mock-data.js` 的 `permModules/permMatrix` 是展示及修改数组；`app.js` 的 `ROUTES/MENUS` 独立使用静态roles。系统勾选当前不影响这些入口。
2. 默认矩阵与现有可达范围不一致：sales/doc/fin 可进入审批台账，却缺“审核与异常”；boss 可查询盘/报价及收款页，却缺“销售业务/收款与应收”。不能直接交集后把默认行为改变伪称兼容。
3. 商品详情允许sales/doc/fin/boss，而商品列表及“客户与商品”菜单仅sales。详情是订单来源查阅的合法路径，必须单独映射，不能套列表模块后切断它。
4. 原 `sys-perm`、`sys-toggle-user` change处理器没有管理员身份检查。系统视图本身拒权不能替代写动作校验。
5. 搜索、岗位路径、工作台快捷入口、待办/铃铛和业务交叉链接各自拼接入口。仅隐藏侧栏仍会留下可见或可访问的停用模块。
6. 原会话读取信任本地演示会话，角色由浏览器内存/存储表示；用户可自行修改JS与存储。当前项目的“不可夺权”指原型内部所有标准动作一致拒绝，不构成恶意客户端安全边界。

独立使用原 `verify-document-workspace.cjs` fixture 做了三个隔离诊断：sales矩阵置空后报价路由仍正常；sales身份触发原sys-perm事件可以给admin数组加入业务模块；同身份触发sys-toggle-user可以改变U003启用状态。均为Node内存副本，无真实用户/账号或项目数据变更。

## 3. 建议的权限模型

有效访问必须同时满足：已登录的有效演示操作者、路由/岗位的静态能力上限、已开启模块、原业务动作资格。矩阵只能收回或恢复上限内权限，不能扩展岗位上限。

- 静态ROUTES.roles仍是页面能力上限；MENUS.roles仍是导航分组上限，不通过勾选改写它们。管理员勾选全部业务模块也不得进入业务页/执行审批。boss开启销售模块仍不能进入quoteEdit、生成报价或订单。
- 用一个共享函数解析有效模块权限，路由、菜单叶子、搜索和业务链接共用。未知角色、未知模块、缺失或畸形矩阵配置默认拒绝；不要以缺失配置默认允许补洞。
- 给路由显式标模块。订单列表和详情统一归“订单详情”，不要因销售侧栏分组名误归销售业务。商品详情建议使用“客户与商品或订单详情”的只读访问依赖，并保原静态roles上限；商品列表仍要求客户与商品。这项映射应落文字契约并单测。
- 默认矩阵显式补齐上述已存在的合法可达范围，或记录经用户明确批准的收缩。不要在权限getter里偷偷补权限，否则管理员取消后会自动恢复。
- 视图与动作均检查有效权限；直接调用Actions、原生submit/change、弹窗回调都不能绕过。延迟保存/审批/收款在commit前重查矩阵，撤权时失败零写、保输入并解除busy。只有app点击委托一处guard不够。
- 审批权限继续由原角色/自审/状态/对象规则决定。模块是入口与动作开关，不能代替这些规则。单证审核、异常审批分别标注实际所属模块，不依据“审核”中文字面自行扩大或合并权限。
- 系统矩阵/用户开关/重置类动作检查当前管理员、系统模块、合法目标及提交时原操作者。非法role/module不新增任意键。内置管理员不可禁用的规则保留；系统管理或工作台防自锁策略由主代理明确选定并展示，不把刷新恢复当成未说明的体验。
- 关闭模块后不应清洗历史业务或快照。当前页面若被撤权，停止相关操作、给原因；导航处理保留原未提交输入保护，避免重绘默默丢字段。

建议权限测试至少覆盖：五岗默认20路由；每个可配置模块关闭后的路由/菜单/搜索/快捷入口；恢复后正常；admin全业务勾选仍拒权；boss销售开启仍无写权；单证员核心字段只读；未知role/module/缺失矩阵拒绝；非admin系统事件零写；正在提交时撤权零写；商品详情合法依赖与停用路径。

## 5. 新功能的必要独立验收

- 首制必须从同一笔新询盘连续走到新订单→首份CI/PL→编辑/送审→不同人主管审核→导出演示，另一支并行收款。首制之前/之后/重复点击核对恰好一份V1、合法唯一编号、完整来源捕获及旧业务零漂移。旧订单已有某类时只补缺类，不能覆盖或重复创建。取消两态、撤权、来源切换、编号冲突均原子拒绝。
- 包装纯数字默认单位要区分界面规范化与事实：数字可按明确KG/CBM规则解释，但空值保持待补，不制造真实重量。沿原三位精度/毛重≥净重/CI无包装门槛。失败保原输入并聚焦首错；成功后的格式说明与纸张一致。
- 改价预试算和主管提交必须调用同一纯候选算法。预览不写订单/申请；目标合法但等比舍入无法命中的结果仍明确拒绝，不因为入口变友好而绕过精确勾稽。验证两币种、已收下限、精度/安全范围、失败零写及延迟内容漂移。
- 报价15天/交期30天按真实日历加天，覆盖月底、闰日、跨年；明确是自然日。生成订单带入实际已确认交期，编辑已确认报价仍禁止。
- 财务全额按钮读实时余额而非旧option数据；部分收款保持上下文，结清清旧预选再续办，所有订单结清给正向空态。下一单不自动提交、不复用上一单金额/币种。超收/并发漂移失败仍原子拒绝并保原输入。
- 首页新增笔数定义为本次页面加载以来成功创建/登记的数量；初始化0，取消/失败不加，重复回调只加一次，刷新还原0，退出重登是否保留与演示内存保持一致并写明。待办排除已有quoteId且只显示仍可办理项。
- 订单页签只改tab body；验证外层节点相同、页面滚动和焦点符合预期、hash和back/forward仍正确。局部更新不能绕过原离开保护。
- 审核续审指向有权且仍可审的唯一当前版本，不自动批准。最终一件完成时有正确空态；本人制单、取消两态、已有新版本和重制pending继续拒绝。
- 主代理浏览器验收覆盖1280/1440、五岗默认矩阵与动态关闭至少代表组合、file局部、键盘/输入保留与console；截图逐张读回，区分像素与CSS尺寸。独立终评只评实际证据，不预写全部通过。

## 6. 交付结论门槛

本轮只有在同一笔新订单首制全链实际闭环后，才可关闭上轮P1；预置单证通过不能代替它。权限变更须在路由、入口、动作及延迟提交均实际生效，仍不能称后端安全交付。未回用户的角色快捷切换问题维持原规则，不阻塞其它独立范围。
