# 第6轮 UI 与五视角验收计划

2026-10-07；基线`d396990f01f044a313bdb60575ef205b4756f8c5`。本代理拥有本计划与`.impeccable/review/round-06/design-review.md`；只读规划、当前core/sales/mock/CSS差异和两份worker说明，不改实现/Mock/规范/Git/HANDOFF，不操作root CUA。以下是方案及待验条件，不预写像素/真实交互PASS或SHIP。

## Task model / 当前岗位任务

客户 Primary task：确认当前客户身份，维护企业及联系资料，修正具名错误后一次保存。Secondary：返回客户列表、查看关联订单。Reference：固定编号/合作起始、旧订单交易与单证快照影响边界。已有客户维护不等于新建客户，当前“新建”仍为演示占位。

询盘 Primary task：读客户留言与意向商品，核对当前参考价/币种/合计，再生成一份可编辑报价草稿。已有双向报价则直接查看关联报价；“跟进中”不能覆盖INQ5已有Q5事实。Secondary：客户/商品/关联报价入口、返回询盘列表。Reference：来源渠道、业务员、日期与内存演示说明。主管查阅询盘/关联报价，不能发起、编辑、登记客户确认；不扩大客户模块ROUTES。

客户/询盘上游写入会影响后续新建来源，UI必须让维护对象与价格来源可辨；主数据名称变化可反映在当前lookup显示，不等于原订单对象/金额被修改。旧纸张交易来自冻结快照，不能要求全站显示名称永不变化，也不能把当前客户档案当原签发身份认证。

## Disclosure / 为什么常显或后置

客户编号和合作起始不是可修改表单目标，但决定维护对象，紧凑常显；邮箱基本格式原因与必填标识影响当前输入，不能藏进FAQ。邮箱是否真实可达、持久化/后台不是当次保存自动承诺，短hint说明即可，不加入验证邮件/DNS步骤。旧订单是参考，后置不能替主表单占据首屏。

询盘留言是真实需求或明确合成示意，不能被巨大来源卡挤到低层；意向数量/当前参考价/币种/行合计必须在核对区。现参考价可能与原Q金额/币种不同，已有报价路径常显简短解释，正式交易以关联Q为准；禁止把已有关联关系按“跟进中”文字重置。

INQ6日期2026-10-07是样例加入日，不是收到客户需求日期；合成标签必须与记录绑定，备注编辑不能抹去。新Q编辑/详情已带标签，建议列表编号下也带同标签，让主管从列表到达时不把它当实盘。合成来源和默认条款待核对是当前决策事实，不能延后或只写测试报告；生成草稿不是正式发给客户，不登记客户确认或自动订单。

询盘商品链接当前不带询盘返回参数，沿第5轮按有权商品/订单列表回退；本轮不猜最近询盘或新增通用历史恢复。若下轮要返回该询盘需明确来源契约，不从浏览器Back推断上下文。

## 首轮小范围UI建议

1. 客户只读身份+企业2行+联系2行+备注/提示/保存纵叠，正常1280高度需实测；若超底先压组间空白或桌面企业/联系组并列，不删字段/hint、不缩字号、不借滚动错误图宣称正常主动作可见。
2. 询盘页头“发起报价”与确认“生成报价草稿”含义不够一致，建议主入口改“生成报价草稿”或“起草报价”；明确仍需编辑/确认，不新加门禁。
3. 合成newQ列表目前只有q.id而详情/编辑有标记，建议该编号下复用cell-secondary合成演示样例，不新列/新卡/新状态。
4. 当前询盘6列表min-width880，商品英名可折行但规格等继承nowrap；1280实际长名/规格核查内部滚动/局部折行，不页级溢出。金额右对齐，H12非法候选待核对而不0/部分总计。
5. 留言与意向表同级主任务，来源仅一段后置参考；545USD必须始终为参考合计，INQ2当前参考USD不能被误当旧Q2EUR成交变更。
6. 编号/合作起始具名只读、邮箱hint+error追加、ABC默认项与失败dirty结构已有正向，仍须实际Enter/错误focus/保原值/修正成功/离开cancel验证，不认领Node像素。

## 可访问性规格、树与标准映射

平台为桌面Web。已有U.formItem与运行label关联、aria-invalid/临时error追加hint、role=alert总结沿用；企业/联系当前h3视觉分组可用aria-labelledby具名region或fieldset/legend表达表单组，不能仅靠左右位置。下面只给语义规格，不编辑运行HTML；基于当前唯一id验证，无重复字段。

```html
<section aria-labelledby="customer-contact-heading">
  <h3 id="customer-contact-heading">联系信息</h3>
  <label for="c-email">邮箱</label>
  <input type="email" id="c-email" aria-required="true"
         aria-invalid="true" aria-describedby="c-email-hint c-email-error">
  <p id="c-email-hint">核对基本邮箱格式；不验证邮箱是否真实可达</p>
  <p id="c-email-error">邮箱格式不正确，请填写如 name@example.com 的基本邮箱地址。</p>
</section>
<p><span>合成演示样例</span> · 样例加入日期 2026-10-07</p>
<button type="button">生成报价草稿</button>
```

预期可访问树：主导航 → 维护客户标题/短dirty → 固定编号/合作起始只读字段 → 企业组具名可编辑字段 → 联系组/邮箱hint+具体错误 → 备注 → 完整错误总结 → 保存 → 关联订单参考。询盘为对象标题/真实状态/合成标识 → 当前任务解释 → 客户留言/意向表具名列与带币种参考合计 → 单一草稿或已有Q入口 → 来源参考；确认dialog具名，客户/INQ与明细、参考合计、待编辑条款、取消/生成草稿可键盘到达。此为预期语义而非真实读屏输出。
