## Task model / 岗位主次任务

Primary task：制单员在当前合法最新版PL核对包装五字段，修正已填错误，先保存合法待补草稿，再补齐送审。保存是保当前进度，送审是完整包装进入主管审核，两者不能被同一“完成”标识混淆。

Secondary：根据退回意见、版本/订单/交易来源核对受控修订或重新制单，安全离开/返回；主管查阅包装与审核意见，但不编辑制单字段。Reference：完整单位语法/范围假设、冻结来源/时间、版本历史、旧审核事实。角色/当前no-Vn/真实状态/必要退回意见常显，长解释后置。

实际包装行在纸张明细下方，正常右栏保存/送审首屏可见不等于全部包装输入都首屏。用户可以自然向下滚动核对再提交；需真实测输入焦点/错误定位与右栏可达，不通过截纸或缩字声称同屏完整。

## H18字段契约与内容说明

| 字段/ID | 当前含义与已填合法值 | 草稿 | 送审 | 就近提示方向 |
|---|---|---|---|---|
| 包装件数/df-pk-cartons | 普通正安全整数；拒0、负、小数、指数、hex、非数/范围外 | 可空待补 | 必填且正 | 整数；这是包装件/箱数原型口径，不是交易商品数量 |
| 包装方式/df-pk-package | 实际文字，不猜枚举/不静默截断 | 可空 | 必填 | 按实际包装填写；若helper新增上限需明确提示/错误 |
| 毛重G.W./df-pk-gw | 显式KG/KGS（大小写可识别），正数最多3dp，标准千分逗号可用 | 可空 | 必填且正 | 例1,680 KGS；明确单位，不猜吨/磅 |
| 净重N.W./df-pk-nw | 同KG/KGS精度/逗号规则；两合法已填时与GW同尺度比较 | 可空 | 必填且正、GW≥NW，可相等 | 原文保留；净重不可大于毛重 |
| 体积MEAS./df-pk-meas | 显式CBM，正数最多3dp，标准千分可用 | 可空 | 必填且正 | 例8.6 CBM；不是长×宽×高字符串 |

点是小数、逗号只作标准千分组；1,680 KGS可用，1,68 KGS不能被猜成1.68或168。合法原字符串只trim首尾，内部表达/大小写/末尾0保留，不自动换单位/洗历史。任意已填非法均阻保存和送审；空是未知、不是0。比较使用有界共同scaled整数，不用浮点或假0判断GW/NW；不声称超大合法形式有实际物流合理性。

H18仅PL。CI不因隐藏packing值被包装必填拦截或改写；H12交易数量0.01/单价金额两位到分不变，不自动把cartons规则套到订单qty，也不从商品数量算出箱数/毛重/体积。实际件单位、计量容差/托盘范围、精度/单位/零与状态完整度仍需企业正式确认，均为可撤销原型假设。

## State model / 不合并单证事实与包装完整度

| 状态 | 判断依据 | Must-see-now | 行为 |
|---|---|---|---|
| 合法最新版查看 | 原docPolicy/角色/no-Vn/订单资格 | 真实草稿/制作中/退回等状态、短来源 | doc可进入编辑；boss/其他角色按原只读/审核资格 |
| 编辑未改动 | 当前字段基线 | 编辑模式、具名五字段/单位 | 无变化放弃直接回只读，保原业务规则 |
| 已填非法 | helper errors[{field,error}] | 对应字段完整原因、原文、首错focus/dirty | 全候选拒绝，日期/历史/状态/审批不先写 |
| GW<NW关系错误 | 两项各合法且共同尺度关系不成立 | 同一关系cause、两字段无效 | 共享一份说明，首错可改；不把空/非法当0 |
| 合法部分/全空草稿 | 每个已填值合法但缺字段 | 包装待补+具体缺项，真实单证状态仍在 | 保存当前合法进度；不说送审就绪/完成或自动改为草稿状态 |
| 部分已保存只读 | 真实草稿保存成功 | 待补字段及进入编辑入口 | 非编辑送审仍拒/明确原因，不凭“已保存”放过缺项 |
| 完整候选待送审 | 五项齐合法且原资格通过 | 包装完整（尚未送审）、当前no-Vn | 一次确认展示当前包装再送审，不自动审核/导出 |
| 实际送审成功 | 入口/实际提交复核同一候选/会话/内容/版本 | 实际待审核与留痕 | 成功才clean/重绘；重复/跨按钮一次，已完成动效不是业务证据 |
| 历史/已通过 | 原审核/快照/版本事实 | 只读真实原包装/章/历史 | 不因H18回洗或自动撤销审核；新草稿可待修正 |
| 受控修订/重制 | 分别沿旧交易/捕当前交易，包装复制来源明确 | 继承/需核对短说明；未自动证明物流匹配 | 旧版留存，新草稿校验/补全后再送审，不以复制直接合格 |

主管审核/导出演示是否新增H18拦截由中枢明确，预案不擅改资格；当前最小范围为保存/送审与两创建路径，旧章保留不等本轮完成真实物流或签发认证。

## Information architecture / 页面信息层级

| 信息 | Role/频率 | 首屏/位置 | 披露方案 |
|---|---|---|---|
| no-Vn/订单/真实单证状态 | Primary context/高 | 既有页头与右栏当前版本 | 保原事实，不加巨型新抬头 |
| 退回意见/创建来源差异 | Decision context/按情境 | 操作前或其紧邻短说明 | 退回原因常显；重制包装继承需核对，不藏在低层历史 |
| 五包装字段与单位 | Primary task/高 | 既有纸张包装行 | 各具名；可滚动到实际输入，不删原纸张字段 |
| 草稿/送审要求 | Supporting instruction/高 | 包装行上方一条短句 | 草稿可空/送审齐；避免五处重复长文与永久required矛盾 |
| 字段错误/待补清单 | Input assistance/失败或部分保存 | 字段就近+可读总原因 | 完整折行，空错误不占高；缺项以具体名字，不只数量 |
| 保存草稿/提交审核/放弃 | Primary actions/高 | 既有右栏前部 | 正常保存/送审目标≤980（1000高）；不加额外批准 |
| 规则/冻结时间/历史 | Reference/低 | 原生details或原参考区后置 | 长语法/现实边界渐进披露，不推走动作 |

数字输入可右对齐，但单位是合法字符串的一部分，KGS/CBM使用能输入文本的控件，不用type=number使单位不可打。箱数可inputmode=numeric辅助，不依浏览器number自动转型认定合法。原“尺码MEAS.”宜改为“体积MEAS.”+CBM，避免误引导尺寸乘式。

## 首轮代码发现与小UI方案

1. 现PL五input只有表头，无自身label/aria-label/错误容器。表格视觉列关系不能代替表单控件名称；建议每个input具名中文+现英文，错误ID/hint关联，DOM唯一。
2. 单条“草稿可空，送审前五项完整；重量KG/KGS、体积CBM，最多3位小数”就近包装行；例子/千分长规则可details。草稿字段不要永久aria-required=true或把空显示0，readonly待补用“待补/—（待补）”。
3. GW<NW两input共享同一cause/aria-invalid，首错focus可改，不复制两段长原因挤列。全原因在数值td内必须white-space正常/overflow-wrap，避免第4轮nowrap横滑；错误态允许纵滚。
4. 保存部分后具体待补清单常显，非编辑送审拒绝要有明确原因与“编辑包装与备注”入口；若选择禁用UI也必须常显理由且真实动作仍复核，不把禁用当校验。
5. 右栏保持角色主动作前置，新增状态/单位提示不要变大说明卡。1280/1440正常bottom由实际DOM验，包装行离页顶远属于作业滚动，不以它的滚态截图冒正常首屏。
6. 修订/重制短说明写清旧包装继承与当前交易需核对，保旧文书/审核章原文；不根据价格/数量变化自动推导新的包装或把复制写成已验证匹配。
