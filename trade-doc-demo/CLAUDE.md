# CLAUDE.md — Claude 代理工作指引

> 本项目由多个 AI 代理（GPT/Codex、Claude 等）协同开发。
> **项目规则、技术约束、业务规则、目录结构、完成标准统一定义在同目录 `AGENTS.md` 中，开工前必须完整阅读 `AGENTS.md` 与 `HANDOFF.md`。** 本文件只补充 Claude 侧的工作方式，不与 AGENTS.md 重复；如有冲突以 AGENTS.md + 需求方最新指示为准。

## 开工流程（每次必做）

1. 读 `AGENTS.md`（规则）→ 读 `HANDOFF.md`（当前状态、上一棒做了什么、遗留风险与待办）。
2. 确认本次任务范围，尽量限定在单个模块/页面内，避免与其他代理的改动面重叠。
3. 动手前先浏览将改动的文件现状——不要凭 HANDOFF.md 的描述直接改，以代码现状为准。

## 完工流程（每次必做）

1. 按 `AGENTS.md` 第 7 节"完成标准"逐项验证（`node --check`、引用路径、五角色渲染、金额勾稽）。
2. **更新 `HANDOFF.md`**：追加交接记录（日期、代理=Claude、任务、改动文件、验证命令与结果、遗留风险、建议下一步），并同步"当前状态速览"与"待办清单"。
3. 若本次改动使 AGENTS.md 中任何规则过时，一并修订 AGENTS.md。

## 针对本 Demo 的特别提醒

- 纯静态、无构建、无 CDN、必须支持 `file://` 双击打开——**不要提议或引入框架/包管理器/构建步骤**。
- Mock 数据是唯一数据源（`js/mock-data.js`），页面数字一律从数据派生，禁止在视图里硬编码业务数字。
- 写操作只改内存、刷新还原，是有意设计，不要"修复"它。
- 交接记录用简体中文撰写，保持简洁、可核对（写清验证命令和实际结果，不要写"应该没问题"）。
