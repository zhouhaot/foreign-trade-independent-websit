# 生产工程规则

## 范围与隔离

- 本目录是独立生产工程，使用 TypeScript、Next.js App Router、Drizzle ORM、PostgreSQL（postgres.js）、Zod 和服务端数据库会话。
- `trade-doc-demo/` 是静态评审基线，不得在本目录任务中修改，也不得向其接入生产数据。
- 业务契约以 `docs/contracts/` 为生产权威契约；契约是设计输入，不代表业务链路已经实现或通过集成验收。
- 后续文档只能引用或落实 `docs/contracts/` 既有契约，不得自行发明业务规则。业务规则变化先更新既有契约并确认冲突。

## 工程边界

- 所有业务数据通过 `/api/v1` 访问；业务写不使用 Server Actions。
- `/api/health` 仅用于进程存活检查，不属于业务 API，也不代替数据库或依赖就绪检查。
- 不在未获对应任务授权时提前实现数据库 Schema、认证、业务模块或部署配置。
- 不在源码、示例配置、日志或报告中写入真实凭据、会话令牌或业务敏感数据。
- 使用服务端环境变量读取秘密；不得把秘密暴露给客户端组件。

## 目录职责

- `src/app/`：App Router 入口、页面和路由处理器。
- `src/server/`：后续服务端基础设施与业务服务；当前仅保留目录。
- 后续业务实现应保持 HTTP 边界校验、授权、事务和数据库访问职责清晰，不在 React 组件中直接执行数据库写入。

## 依赖与脚本

- 使用 pnpm，依赖版本由 `pnpm-lock.yaml` 锁定；不要混用 npm 或 yarn 生成锁文件。
- Node.js 版本须满足 `package.json` 的 `engines` 与各依赖要求。
- 提交前按变更范围运行 `pnpm lint`、`pnpm typecheck`、`pnpm test` 和 `pnpm build`。
- Vitest 当前允许无测试通过；新增业务行为时必须添加对应测试，不能把空测试结果当作业务验收。
- Playwright 已安装，但真实浏览器验收、数据库集成和部署验收尚未执行。

## 完成标准

- 仅报告实际执行且通过的检查；构建成功不等于业务、权限、数据库或生产就绪。
- 新文件和生成产物检查后再交付，不提交 `node_modules/`、`.next/`、测试报告或秘密文件。
- 不执行 Git 提交或推送，除非用户另行明确授权。
