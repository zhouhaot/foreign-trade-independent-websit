# 首个业务切片权限与事务契约

本契约用于生产实现与验收，不代表后端已完成。接口见 [OpenAPI](slice-01.openapi.json)，字段与复合键见 [数据模型](DATA_MODEL.md)。正式身份不得来自 Demo 角色下拉框、请求体或客户端存储。

## 首切片岗位边界

| 接口对象 | 外贸业务员 | 业务主管 | 管理员/单证员/财务 |
|---|---|---|---|
| 当前身份与退出 | 自己 | 自己 | 自己 |
| 启用币种与共享商品读取 | 公司目录 | 公司目录 | 本切片未开放销售目录接口 |
| 共享商品维护 | 具备对应权限可写，版本冲突拒绝 | 只读 | 拒绝 |
| 客户与询盘 | 本人读取/创建；客户可版本化修改 | 全部只读 | 拒绝 |
| 报价草稿及提交/确认/成单 | 本人对象、当前状态及权限均满足才可写 | 全部只读 | 拒绝 |
| 订单读取 | 本人 | 全部 | 本切片暂不开放，后续按职责设计 |

主管全量读取不等于代业务员写入。后续主管审批仍不得自审，管理员无业务审批权。其他岗位本切片拒权不是永久移除职责，而是暂不发布相应生产能力。

## 数据库会话与 CSRF

- 同源 HTTP 应用使用 `TRADE_SESSION`  opaque 随机会话 Cookie；生产必须 `Secure`、`HttpOnly`、`SameSite=Lax`、`Path=/api/v1` 且不设置宽泛 `Domain`。数据库只存会话令牌哈希，禁止把原始令牌放 URL、业务 JSON、Git 或日志。
- `GET /auth/csrf` 为匿名或登录会话返回绑定 CSRF 令牌并禁止缓存，数据库只存其哈希。登录、退出及每个业务写都必须校验 `X-CSRF-TOKEN`；JSON 或内网部署不能替代 CSRF。
- 登录成功轮换随机会话标识和 CSRF 令牌，并将匿名数据库会话转为已认证会话；前端重新获取 CSRF。退出撤销服务端会话，而不只是删浏览器 Cookie。
- 每个受保护请求重新核查用户启用、`auth_version`、会话过期/撤销和有效权限。停用、改凭据或撤权后旧会话不得继续写。
- 密码只存经选型的自适应单向哈希，参数按目标硬件测试；登录失败统一提示并限流，不区分账号不存在、停用或密码错误。
- Route Handler 默认拒绝，服务层再次执行操作授权与对象范围。归属条件进入 Drizzle 查询，而不是查出全量后由浏览器过滤；写入前重查权限和字段白名单。

账号初始化、密码重置、会话空闲/绝对超时、限流阈值和兼岗仍须锁定。本切片不创建默认生产账号或身份切换接口；测试只用合成账号，测试配置不得随生产包启用。

## 输入与错误

所有业务写 DTO 通过 Zod 严格拒绝未知属性，特别是 `ownerUserId`、`actorUserId`、`role`、`status`、`totalAmount` 和客户端审计时间。日期、正数、小数精度、长度、行数、字典、来源 ID、状态和版本均须服务端校验；JSON 语法正确不代表业务合法。

| 状态码 | 用途 |
|---|---|
| 400 | JSON 语法、非法查询/路径格式、缺少或格式错误的幂等请求头 |
| 401 | 未登录、会话过期/撤销、账号禁用；登录失败统一响应 |
| 403 | 已认证但岗位/操作权限不足，或 CSRF 不匹配 |
| 404 | 对象不存在或不属于有权范围；不得返回客户名/金额等线索 |
| 409 | 状态/乐观版本/来源资料变更、幂等键冲突、唯一性冲突 |
| 422 | 字段值、真实日历日期、非整分、超界、资料不完整等业务输入错误 |
| 429 | 登录或接口限流 |

`Error` 包含稳定 `code`、中文 `message`、`requestId` 及必需 `fieldErrors` 数组；无字段错误时为空数组，不返回堆栈、SQL 或认证细节。对象字段/版本错误只能在授权和归属检查后返回。列表 `items`、`total`、搜索/筛选和聚合使用同一归属条件。

## 幂等与版本

除登录/退出外，每个业务写必传 `Idempotency-Key`。键在同一真实操作人内跨接口唯一；请求指纹包含 `operationId`、路径、查询及规范化业务 body。对象键顺序规范化、十进制等值统一，不将密码、Cookie 或 CSRF 放入指纹或持久响应。客户端重试同一操作复用原键，新动作使用新键。

同键同指纹已成功时返回同一资源的当前授权表示，HTTP 200 并带 `Idempotency-Replayed:true`；只保证原业务效果不重复，不保证响应字节或旧字段/版本相同。创建首次成功 201，更新首次成功 200。不可变确认/订单版本仍保持历史内容。同键异接口、路径或内容返回 409。幂等记录与业务、成功审计同一事务，失败全回滚；暂不自动清理键。

幂等重放前先核查当前身份、启用、权限和资源归属，不能直接回放缓存数据。重放已成功结果允许原 `expectedVersion`；非重放的新写入必须严格匹配最新版本。事务内重新检查条件，409 时不自动合并覆盖。

## 事务边界

| 动作 | 一次成功必须共同提交 |
|---|---|
| 创建商品/客户 | 合法字段、唯一性/归属、记录与版本、幂等记录、成功审计 |
| 修改商品/客户 | 角色与归属、原 `row_version`、完整候选、`row_version+1`、幂等及审计 |
| 创建询盘 | 客户归属及版本、商品版本和快照、全部询盘行、父记录、幂等与审计；任一行错误全部不写 |
| 询盘起草报价 | 询盘来源/版本、复制全部行与快照、DRAFT 报价、询盘 QUOTED、幂等及审计；并发也只能一份首报 |
| 保存报价草稿 | 同一报价完整原行集合、精确金额、币种/条款/日期、草稿状态、原版本、全部明细及总额 |
| 提交待确认 | 原版本与来源客户/本公司预览版本、完整交易候选、`issued_snapshot`、AWAITING_CUSTOMER、幂等及审计 |
| 登记客户确认 | 原版本/待确认状态、必填确认记录、逐值复制 `issued_snapshot`、CONFIRMED、幂等及审计 |
| 报价成单 | 原版本/确认记录、唯一订单、V1 与全部行、确认快照复制、`quote.converted_at`、幂等及审计 |

所有步骤在同一个 Drizzle/PostgreSQL 事务中执行。并发控制按“认证/授权上下文 → 幂等键占位 → 来源聚合根 → 行/依赖”固定锁序；更新草稿、提交、确认和成单在同一报价聚合上使用行锁或等价原子版本条件。具体隔离级别、唯一冲突回读和有限重试必须在真实 PostgreSQL 验收，不能用内存结果代替。

## 成单重试与竞争

首切片每询盘一份报价，每报价至多一张订单，不存在通用 `POST /orders` 或核心订单修改接口。

成单先检查同一有权来源报价是否已有订单。同键成功重放返回已有结果 200；新键但 `deliveryDate` 与 V1 一致也返回同一订单 200，不重复写业务审计；交期不同返回 409 `SOURCE_ALREADY_CONVERTED`。读取分支可接受最初 `expectedVersion`，但必须重新鉴权；无既有订单的新写分支才检查期望版本、确认和有效期并创建，首次成功 201。

`sales_order.source_quote_id` 唯一约束是最终兜底。两个不同键竞争同一来源时也不能出现两行订单；冲突回读须再次校验交期和当前授权。快照、明细、关联、审计或幂等任一步失败，整个事务回滚；唯一约束异常不能包装为假成功。

## 验证边界

静态检查只验证逻辑键、OpenAPI 引用、DTO 白名单、金额类型、权限标记、验收映射和反例。真实鉴权、CSRF、外键、并发、事务回滚、文件权限和重启持久化必须由后续集成用例验证；验收矩阵中的 `PLANNED` 不是 `PASS`。
