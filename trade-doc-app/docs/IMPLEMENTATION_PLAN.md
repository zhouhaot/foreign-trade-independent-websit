# 生产工程首切片实施基线

日期：2026-10-29。目标是公司内部可持续使用的独立生产应用。当前交付为权威契约与架构决策，不表示业务链路、数据库迁移或部署验收已完成。

## 已确认范围

- 面向本公司内部员工，约 15 人；总人数与同时在线数仍需区分。
- 单机服务器部署；具体操作系统、CPU、内存、存储、TLS 和备份条件在部署前补齐。
- 业务员只能查看本人负责业务，主管可全量只读；列表、详情、搜索、统计、导出和附件下载必须使用同一数据范围。
- 首版只录新业务，不迁移历史 Excel、订单或 Demo 样例。
- 商品为公司共用目录；客户确认附件可选，但方式、日期、说明必须记录；数量和单价各最多两位且行金额必须精确到分。
- 保留五岗位、已确认报价成单、单证与收款并行、三类进度独立、禁止自审、管理员无业务审批权、分币种金额及已审版本不覆盖等既有规则。

## 工程隔离与边界

`trade-doc-demo/` 保持静态历史参考，不接入生产数据，不修改其 `file://` 能力。正式应用不提供任意身份切换，不信任请求体、客户端存储或演示角色传来的操作人、归属和岗位。

所有业务数据经同源 `/api/v1` 访问，业务写只由 Next.js Route Handlers 接收，不使用 Server Actions。HTTP 边界使用 Zod 严格校验，服务端执行授权、归属过滤、十进制计算和 PostgreSQL 事务；React 组件不直接写数据库。

旧根目录草案中的 Spring Boot、MySQL/MyBatis、Vue 及默认答案仅是历史候选，不是现行决策。现行技术选择见 [ADR](architecture/README.md)，旧草案不得覆盖本目录契约。

## 首切片必须证明

| 交付 | 放行证据 |
|---|---|
| 真实账号与数据库会话 | 停用后拒绝操作；退出撤销服务端会话；登录轮换会话与 CSRF；匿名登录也有 CSRF 防护 |
| 数据归属 | A/B 业务员列表、详情、搜索和计数无越权；篡改 ID/JSON 不能绕过；主管全量只读 |
| 服务端字段与金额 | 未知字段拒绝；归属、状态、审计和总额由服务端生成；逐行整分且不使用 JavaScript `Number` 结算 |
| 报价生成订单 | 确认来源、明细、快照、关联、转换标记、幂等与审计同事务；重复/并发最多一张订单 |
| 持久化与恢复 | 刷新及服务/数据库重启后可回读同一订单；故障注入无半张订单 |

## 交付顺序

| 阶段 | 工作 | 放行标准 |
|---|---|---|
| 一 | 契约与架构 | 16 表、25 操作、49 场景静态检查通过；技术 ADR 齐全；业务未决项不被擅自关闭 |
| 二 | 登录与报价成单真实切片 | 真实 PostgreSQL 上完成安全、并发、事务、重启测试，浏览器完整走通 49 项中相关场景 |
| 三 | CI/PL、审批与导出 | 订单版本绑定、不可覆盖、自审拒绝、模板样本和下载授权通过；规则须另行确认 |
| 四 | 收款与异常 | 同币种并发余额、重复登记、改价、取消和冲销按获批规则验收 |

不引入微服务、消息队列或独立工作流平台。后续模块不能因首切片工程已建立而默认获批。

## 仍需收敛

1. 报价过期补录/成单、确认/询盘/交期日期区间、报价修订、订单后续状态。
2. 兼岗、业务流水号、账号开通/重置、会话超时与限流参数。
3. CI/PL 编号与模板、修订生效时点、收款冲销/退款规则。
4. 服务器规格、秘密管理、备份保留、恢复目标和运维责任人。

任何未决规则不得由代码默认值伪装成业务批准。正式验收前，49 个场景继续保持 `PLANNED`。
