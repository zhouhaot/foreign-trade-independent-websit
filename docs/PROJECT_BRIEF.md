# 项目业务与技术边界草案

## 已确认方向

题目：基于 Spring Boot 的外贸订单与单证管理系统的设计与实现。
面向单个外贸企业的内部业务协作，借鉴 ERP 的订单贯通思想，不建设完整 ERP。五个角色为系统管理员、外贸业务员、单证员、财务人员、业务主管。原描述末项“业务人员”暂按业务主管处理。
业务链路：询盘 → 报价单 → 报价确认 → 生成订单 → 制单和审核 → 导出单证；收款登记和应收统计围绕订单并行开展，不要求收款必须发生在制单之后。
AI 是研发工具，不是业务系统必需的运行依赖。首版不增加智能报价、AI 审核或聊天入口。

## 建议的第一版范围（待业务确认）

单企业、内部五角色；支持报价修订，已确认报价整体转换为一张订单，不拆单、不合单。客户无需新增第六个登录角色，由业务员记录线下/邮件确认和确认凭据。
包含登录与权限、基础字典、客户与商品、询盘、报价及确认、订单、商业发票与装箱单、单证审核导出、收款应收、主管统计、异常申请与审计日志。
暂不实现采购、库存、生产、报关申报、出口退税、银行支付、汇兑核算、复杂信用证或多租户。单证为业务管理模板，不能表述为已通过海关/银行合规认证。
首版部署候选为 Java 21 + Spring Boot + Spring Security + MyBatis + MySQL，前端 Vue 3 + TypeScript + Element Plus；数据库迁移使用 Flyway。使用模块化单体，不引入微服务、消息队列或独立工作流引擎。具体依赖版本在启动检查后锁定，避免混用不兼容组件。

## 角色与数据责任

| 角色 | 主要写入内容 | 首版限制建议 |
|---|---|---|
| 系统管理员 | 用户、角色、菜单授权、基础字典 | 不因管理员身份自动拥有审批业务或修改收款的权限；订单状态字典只维护展示和可选项，不能任意改变状态转换逻辑 |
| 外贸业务员 | 客户、商品、询盘、报价、确认凭据、订单前端交易信息 | 只管理本人/授权范围客户与订单；确认后核心交易信息通过变更申请修改 |
| 单证员 | 包装件数、唛头、重量、体积、备注、制单及送审 | 不得修改客户、商品、成交价、币种、订单数量等核心交易数据 |
| 财务人员 | 收款、应收核对、收款冲销申请 | 不改报价、订单或单证核心内容；错误记录通过带原因的冲销留痕，不物理删除 |
| 业务主管 | 关键单证审批、订单取消/改价/重新制单审批、统计 | 批准受控操作而非直接覆盖原数据；禁止审批自己发起的申请 |

角色菜单只是界面表达；后端必须同时校验操作权限、数据归属、字段修改权限。导出和文件下载同样需要授权。

## 状态模型建议

报价：草稿 → 待确认 → 已确认 / 已拒绝 / 已过期。已确认报价需修改时建立新修订并重新确认；记录转换关系，不能重复成单。
订单：待执行 → 执行中 → 已完成；允许在定义好的状态申请取消。修改不能用任意 PATCH 绕过审批。
单证：草稿 → 待审核 → 已审核 / 已退回；旧版本可标记已作废。生成文件的成功/失败与导出记录独立保存，不用“已导出”覆盖“已审核”。已审核单证修改包装或备注也必须重新形成修订并送审。
收款状态：由有效收款记录计算为未收款/部分收款/已收齐，不由用户自由设置。订单状态、单证状态与收款状态分开建模，联动规则须明确。

## 核心不变条件

1. 未确认、已过期或无权访问的报价不能生成订单。同一已确认报价在首版只能生成一张有效订单；重复/并发请求返回既有订单或明确冲突，不能重复落库。
2. 报价转订单在同一事务中复制明细、创建确认信息快照并登记关联。客户/商品主数据后来修改，不应追溯改变历史订单。
3. 订单核心数据变更必须经过申请和批准。新订单版本使依赖旧数据的单证失效并待重新生成/审核，保留历史文件和原因。
4. 单证版本记录订单版本与模板版本。正式导出仅允许有效已审核版本；草稿预览应有明确水印，不冒充正式文件。
5. 单证员的包装字段由业务校验约束；商品交易数量只从订单读取。必要包装信息缺失时阻止相关单证正式生成，不自行补造。
6. 应收余额按同一订单同一币种计算：有效应收金额 − 有效实收金额。首版仅同币种收款，不把不同币种直接求和；不实现汇兑损益。
7. 金额使用十进制定点表示，Java 使用 BigDecimal，数据库使用 DECIMAL；币种精度和舍入规则统一定义。不能把前端浮点计算当成最终结算值。
8. 首版建议拒绝超额收款，并阻止订单金额调整到已收金额以下。已有收款的取消申请在退款/冲销规则未实现前应阻塞，而不是把应收直接清零。
9. 所有审批、修改、冲销、导出留存操作人、时间、原因、前后版本。不通过删除记录掩盖历史。
10. 多角色账号的权限冲突需要明确定义。首版可限制每个业务账号仅绑定一个业务角色；管理员账号单独使用，并保留禁止自审的检查。

## 核心数据对象

用户/角色/权限/字典；客户/客户联系人；商品；询盘及明细；报价主表/明细/修订/确认凭据；订单主表/明细/版本快照；单证主表/版本/包装信息/文件；审批记录；收款及冲销；变更申请；操作与导出日志。
这是概念模型，不是已经批准的数据库建表稿。数据库代理须进一步定义外键、唯一约束、金额精度、索引、事务范围和迁移脚本。
