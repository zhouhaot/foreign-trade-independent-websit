# 验收与证据合同

## 关键场景

| 编号 | 场景 | 预期 |
|---|---|---|
| AC-01 | 五角色分别登录 | 菜单和后端操作权限均匹配 |
| AC-02 | 业务员A请求业务员B订单/下载文件 | 拒绝越权且不泄露内容 |
| AC-03 | 未确认或过期报价尝试转订单 | 明确拒绝，不落新订单 |
| AC-04 | 同一确认报价重复/并发转订单 | 首版最多一张订单；唯一约束与事务有效 |
| AC-05 | 转订单中途注入异常 | 订单、明细、转换标记整体回滚 |
| AC-06 | 修改客户名/商品价后查看旧订单 | 历史交易快照不改变 |
| AC-07 | 单证员在API请求中夹带价格/数量 | 后端拒绝或按明确契约处理，不产生交易改动 |
| AC-08 | 单证金额数量与订单核对 | 与绑定的订单版本一致 |
| AC-09 | 已审核单证被修改备注/包装 | 新版本待审；原版本可追溯 |
| AC-10 | 导出未审核/已作废/旧版单证 | 拒绝正式导出；预览有清楚状态标记 |
| AC-11 | 已批准订单改价 | 新版本生效；相关单证失效待重制 |
| AC-12 | 一张合成订单金额1000，收款300和200 | 同币种余额500；不是实测结果，仅为测试输入与预期 |
| AC-13 | 收款重复/并发/超额提交 | 不重复计入，超额按首版规则拒绝 |
| AC-14 | 收款冲销 | 原记录保留，余额正确恢复，原因/操作者可查 |
| AC-15 | 不同币种统计 | 分币种显示，不直接相加 |
| AC-16 | 申请人尝试审批自己申请 | 拒绝；多角色也不能绕过 |
| AC-17 | 已有收款订单申请取消 | 在退款/冲销规则未满足时阻止，不抹去债权/流水 |
| AC-18 | 浏览器完整流程及服务重启 | 可复现且数据持久化 |
| AC-19 | 全新环境运行迁移与演示脚本 | 不依赖开发者私有数据或遗漏文件 |
| AC-20 | Git提交与单证导出安全 | 无真实客户信息或密钥；文件访问受控 |

## 测试分层

单元测试：金额、状态转换、权限决策、幂等规则。
集成测试：真实MySQL行为、唯一约束、事务回滚、并发与文件生成。
浏览器E2E：按五角色完成核心链路；验证按钮之外的接口授权。
人工验收：单证排版、中英文/分页、业务含义、答辩演示。
上述测试工具和环境需在项目初始化后配置。建议JUnit/Mockito、Testcontainers与Playwright；这些建议不代表本包已有测试。

## 必须保存的证据

任务ID、需求ID、实际模型ID、被测提交SHA、测试命令、退出码、执行用例数/通过/失败/跳过、报告路径、复现步骤、审查发现与处理结论。
零用例执行不算通过，跳过必须说明原因。模型审查不能替代CI；运行通过不能替代业务验收。发布报告不得混用不同提交的测试结果。
