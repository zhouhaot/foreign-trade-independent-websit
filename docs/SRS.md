# 需求规格草案（SRS）

版本：DRAFT-0.1（2026-09-20）。状态：**草案，待用户确认**。
依据：`docs/PROJECT_BRIEF.md`（业务构想）、`docs/ACCEPTANCE.md`（验收场景）。
规则：本文档不发明 PROJECT_BRIEF 之外的业务事实；每条需求标注来源与验收标准；标注 ⚠ 的条目存在待确认争议，汇总见 `docs/OPEN_QUESTIONS.md`。

## 0. 项目定位

R-000 系统为**单个外贸企业内部**的订单与单证协作管理系统，服务毕业设计《基于 Spring Boot 的外贸订单与单证管理系统的设计与实现》。借鉴 ERP 订单贯通思想，不建设完整 ERP。AI 仅为研发工具，不是系统运行依赖；首版无智能报价、AI 审核或聊天入口。（来源：PROJECT_BRIEF §已确认方向）

核心业务链路：**询盘 → 报价单 → 报价确认 → 生成订单 → 制单和审核 → 导出单证**；收款登记与应收统计围绕订单并行开展，不要求收款发生在制单之后。

| REQ-AUTH-01 | 系统提供五角色登录：系统管理员、外贸业务员、单证员、财务人员、业务主管。原描述"业务人员"按业务主管解释 | 五角色分别登录成功，会话隔离 | AC-01 |

## 10. 首版边界（明确不做）

不实现：采购、库存、生产、报关申报、出口退税、银行支付对接、汇兑核算、复杂信用证、多租户、拆单/合单、退款自动清算。单证不做海关/银行合规表述。（来源：PROJECT_BRIEF §建议的第一版范围）
