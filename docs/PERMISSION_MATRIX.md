## 2. 防自审与权限冲突规则

1. 任何审批操作中 `申请人 == 审批人` 必须被后端拒绝（AC-16），以用户 ID 判定，不以角色或会话判定。
2. 首版每个业务账号仅绑定一个业务角色（REQ-AUTH-05 ⚠Q-04）；管理员账号不参与业务审批。若未来放开多角色，防自审检查仍按"该申请的发起人"判定，不因多角色绕过。
3. 数据归属校验独立于操作权限：即使拥有"订单查看"操作权限，业务员仍只能访问本人/授权范围订单（AC-02）。
4. 授权范围（如主管代管某业务员的客户）如何定义与维护 ⚠Q-07，首版可先只做"本人数据"，主管全局只读。

## 3. 后端强制校验清单（实现时逐条测试）

- 每个写接口校验：登录态 → 操作权限 → 数据归属 → 字段级修改权限（见 FIELD_RESPONSIBILITY.md）。
- 文件下载/导出接口与页面权限同源校验，禁止仅靠前端隐藏按钮（AC-01/02/10）。
- 越权响应不泄露资源存在性与内容（统一 403/404 语义，P2 契约阶段定稿）。
