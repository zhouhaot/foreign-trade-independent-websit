# 模型岗位和接入检查

## 初始分配

| 研发岗位 | 初始模型 | 交付 | 审核 |
|---|---|---|---|
| 总控/需求负责人 | Kimi K3 | 需求草案、任务卡、状态台账、集成结论 | 用户确认业务，DeepSeek 交叉检查一致性 |
| 架构/数据负责人 | DeepSeek Pro（实际版本待核实） | 架构、ER 设计、状态机、API 契约、关键约束 | Kimi K3 |
| 后端实现 | GLM-5.3 | Spring Boot 代码、迁移、单元测试、缺陷修复 | DeepSeek 独立审查；Kimi 验证任务证据 |
| 前端实现 | Qwen3.8-Max | 页面、权限交互、接口联调、前端测试 | GLM 独立审查；Kimi 核对需求 |
| 独立测试与复核 | DeepSeek/Kimi 的独立测试会话 | 边界/越权/并发用例、复现报告 | 确定性自动测试结果 + 总控核验 |
| 材料整理 | Qwen3.8-Max | 使用说明、论文事实提纲、截图索引、演示脚本 | Kimi 对照实际系统和真实资料审核 |

不是四模型能力排名。同一模型可以担任多个岗位，但必须分离上下文、权限和任务输出。编码者不能充当其改动的唯一审查人。测试运行和 CI 不必由模型“思考”，使用固定命令执行。

## 接入结构

优先复用已经使用的中转接口：Claude Code 主会话/子代理 → 同一个兼容入口 → 按实际模型 ID 路由四模型。仅当现有入口不能稳定服务全部模型时，才增加路由网关，或用独立 Claude Code 实例分别连接不同服务商。

角色提示词里的模型名称不构成真实路由；一份 models.json 也不会被 Claude Code 自动执行。实际配置须写入受当前版本支持的模型配置/子代理定义/工作流参数，并用请求日志验证。
原生子代理可以配置模型，但不能据此假定每个子代理能独立设置服务商 URL 和 API Key。单会话跨服务商通常需要统一入口；独立进程可各用自己的凭据与配置。
Anthropic 官方文档明确：不为通过网关连接非 Claude 模型提供官方支持。Kimi 等厂商可能提供兼容接口，这不等于第三方组合已经通过本项目实测。

## 原生 Dynamic Workflows

官方文档已有 Dynamic Workflows：JavaScript 脚本负责执行顺序、分支和子代理编排；项目脚本可保存在 `.claude/workflows/`。本地先检查 `claude --version`、`/config` 和 `/workflows`，再检查 `/workflow-authoring` 是否可用。
本项目应拆分为需求、设计、单功能实现、发布验收等独立工作流。官方运行时不提供运行中途的业务确认交互，因此需要用户签字的阶段不能塞进一个连续工作流。
不要假定在 headless `claude -p` 的提示中写一个 ultracode 就会触发原生工作流。以本地版本能力、工作流授权和当前官方说明为准。不要直接照搬聊天中未验证的 `agent()` 参数。
原生 Workflow 不可用时，使用同样的任务卡与审核关卡，以普通子代理串行/受控并行执行；不得声称已经启用了原生模式。

## 配置验收

逐个记录：显示名称、真实请求 model、响应 model、接口服务商、端点、是否固定版本、允许的上下文与输出上限、工具调用能力、用量日志。凭据仅留在本地环境或秘密管理中。
模型的自我介绍不能证明底层模型身份；中转返回的 model 字段也是服务商声明，应结合平台路由说明与日志，不能当作模型权重的独立认证。
检查已有全局/项目级模型映射和 `CLAUDE_CODE_SUBAGENT_MODEL`，避免把所有代理意外固定到同一个模型。具体优先级随 Claude Code 版本变化，应核对安装版本和实际请求。

最小冒烟测试：读取指定文件 → 修改一处测试夹具 → 执行测试 → 读取失败输出 → 修复 → 返回结构化证据。另测流式输出、工具调用参数、子代理路由、长输出、取消/错误处理。未获预算授权时只检查配置，不发起付费测试。
同一任务、同一基线、同一测试用例比较模型的首次通过率、严重错误、工具失败、修复轮数、实际费用和总耗时。不用通用排行榜代替项目内验收。

建议初始最多两个写代码任务并行。短时错误最多重试两次；鉴权错误立即阻塞；额度不足先保存任务状态，不能无限重试。跨模型降级必须记录实际模型，不得暗中把不具备工具能力的聊天模型当成编码代理。
